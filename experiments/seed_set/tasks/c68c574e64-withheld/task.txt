fix: remove a stale result file before every command and provider call

A command or provider call delivers its result as a JSON file at
ORCHESTRATOR_OUTPUT_BUNDLE_PATH. The runtime only created the parent
directory, so a file left by an earlier loop iteration, an earlier run or an
interrupted or failed attempt satisfied a call that wrote nothing. The runtime
now removes any file at the bundle path before each command and provider call,
including provider retry attempts; a call that writes nothing fails with
missing_bundle_file. Supervision, peer-group and phased-delivery calls keep
their own absence rule.

A check (`dev-check.json`, run by `python dev_check.py`) runs a test that is kept out of the repository; it fails now and should pass once the change is made. Leave `dev-check.json` and the existing tests unchanged; you may add new tests.

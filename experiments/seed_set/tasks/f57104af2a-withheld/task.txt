Keep __pycache__ out of command closure evidence

A declared directory's walk skips entries named __pycache__ at every level,
so bytecode another process writes into a declared Python package between a
commit and a resume, or during an attempt, no longer diverges the effect or
fails it as a closure write. Python ignores a __pycache__ file whose source
is missing, so those files derive from bound sources; a .pyc outside
__pycache__ (the sourceless layout Python does load) and any explicit entry
naming a file stay bound. C5 lists __pycache__ contents as outside the
promise.

The change is in orchestrator/workflow/evaluated/closure.py.

A check (`dev-check.json`, run by `python dev_check.py`) runs a test that is kept out of the repository; it fails now and should pass once the change is made. Leave `dev-check.json` and the existing tests unchanged; you may add new tests.

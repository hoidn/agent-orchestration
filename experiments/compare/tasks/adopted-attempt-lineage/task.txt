Add a recovery class to the retirement-evidence tooling for an attempt that the owner personally adopted but that never reached its controlled commit, because its workspace-baseline HEAD is not the intended commit predecessor and the commits in between change a path that no retirement-control trailer covers.

Context at the base. `orchestrator/retirement/` holds migration-evidence tooling. `attempt_migration` captures, validates, applies and postvalidates `attempt_migration_disposition.v1`, which archives a failed attempt that stopped before owner adoption and restores the tracked live ledger; its CLI is `python -m orchestrator.retirement.attempt_migration` with `capture`, `validate`, `apply` and `postvalidate`. `source_bindings` captures workspace baselines and builds and reconstructs commit-control trailers. `broad_evidence` builds and validates broad evidence, known-failure baselines and review bindings. `materialization` writes and validates numbered materialization generations. Owner attestation records move from `evidence_status: pending_owner_confirmation` (an immutable snapshot) to `owner_confirmed` (with `owner`, `owner_confirmations` and `owner_adoption`). The v1 disposition cannot describe the new case: it states that the attempt stopped before adoption.

Required behaviour. Version 1 records, fixtures, validation, apply, replay and postvalidation keep exactly their current behaviour; everything below is additive. Production code and schemas carry no queue, workflow-family, module or repository-specific names. Lifecycle facts are derived from files and Git objects, never from caller-supplied flags.

1. Committed predecessor lineage. `orchestrator.retirement.source_bindings.derive_committed_predecessor_lineage(repository_root, *, baseline_head, intended_predecessor_head, require_uncovered_paths=False) -> dict` returns the closed projection of the first-parent commits after `baseline_head` up to and including `intended_predecessor_head`, oldest first:
   - keys `baseline_head`, `intended_predecessor_head`, `intended_predecessor_tree`, `first_parent_commits`, `commit_count`, `changed_paths`, `changed_path_count`, `changed_path_set_sha256`, `controlled_paths`, `controlled_path_set_sha256`, `uncovered_paths`, `uncovered_path_set_sha256`, `normalized_projection_sha256`;
   - each commit row: `commit`, `parent` (its first parent), `tree`, `raw_message_sha256` (`"sha256:"` + SHA-256 of the raw commit message bytes), `changed_paths` (sorted), `changed_path_set_sha256`, and `control_coordinates`: `{"transaction_id": <64 hex>, "normalized_control_sha256": "sha256:" + <64 hex>}` when the message ends with a valid retirement-control trailer block (a blank line, then `Retirement-Control-Schema: precommit_control.v1`, `Retirement-Transaction-ID: <64 hex>`, `Retirement-Control-SHA256: <64 hex>`, as the commit controller writes it), otherwise null;
   - a path set digest is `"sha256:"` + SHA-256 of the sorted paths, each followed by `"\n"`; `controlled_paths` are the paths changed by trailer-carrying commits, `uncovered_paths` those changed by commits without one, `changed_paths` their sorted union; `normalized_projection_sha256` is the module's usual canonical SHA-256 of the projection without that key.
   - It raises the module's `SourceBindingError` when `baseline_head` is not an ancestor of `intended_predecessor_head`, when the first-parent range contains a merge, when a commit or object is missing, when a commit's trailer block is present but malformed, when a commit's changed-path projection lists a path twice, and, with `require_uncovered_paths=True`, when no uncovered path exists (a fully trailer-covered range is not eligible for this recovery).

2. Incident record `attempt_migration_incident.v1`. `orchestrator.retirement.attempt_migration.build_attempt_migration_incident(repository_root, *, governing_plan_path, migration_plan_path, workspace_baseline_path, owner_attestation_path, pending_attestation_snapshot_path, known_failure_baseline_path, expected_paths_manifest_path, source_root, intended_predecessor_head) -> dict` builds, and `validate_attempt_migration_incident(repository_root, record)` returns the record unchanged when it validates and otherwise raises `AttemptMigrationError` (whose message is `<code>` or `<code>:<detail>`).
   - Keys, exactly: `schema_version` (`attempt_migration_incident.v1`), `governing_plan_binding`, `migration_plan_binding`, `workspace_baseline_binding`, `owner_attestation_binding`, `pending_attestation_snapshot_binding`, `known_failure_baseline_binding`, `expected_paths_manifest_binding` (with `row_count` = the number of expected paths), `source_root`, `intended_predecessor` (`{"head", "tree"}`), `predecessor_projection` (the item 1 projection from the workspace baseline's HEAD to the intended predecessor, requiring uncovered paths), `pre_move_repository_state` (the repository state exactly as the v1 disposition records it: `head`, `tree`, `index_sha256`, `status_projection` with `rows`, `row_count`, `normalized_rows_sha256`), `attempt_rows` (one row per attempt file under `source_root` with `path`, `file_type`, `lstat_mode`, `size`, `sha256`, `tracked_state`), `attempt_path_count`, `attempt_path_set_sha256`, `normalized_attempt_row_set_sha256`, `adoption_facts`, `normalized_incident_sha256`, `claims_not_made`.
   - File bindings use the v1 binding format (`path`, `size`, `sha256`); digests and canonical encoding follow the v1 disposition's conventions.
   - `adoption_facts` = `{"adoption_state": "owner_adopted", "repository_commit_state": "uncommitted", "evidence_status": "owner_confirmed", "owner_identity", "owner_role", "confirmed_at", "adopted_at"}`, taken from the owner attestation's `owner.identity`, `owner.role`, `owner_confirmations.confirmed_at` and `owner_adoption.adopted_at`. A pending attestation, a missing owner/confirmation/adoption object, or an adoption identity different from the owner identity raises `incident_owner_lifecycle_invalid`.
   - `claims_not_made` = `["This incident makes no claim that the bound uncommitted attempt was sealed because its recorded workspace-baseline HEAD does not equal the intended commit predecessor."]`.
   - The known-failure baseline is reopened with the existing broad-evidence validators, tolerating only the historical candidate drift the attempt already shows (for example `candidate_path_set_live_mismatch` for candidate paths that have since landed); any other defect raises `incident_known_failure_baseline_binding_invalid:<sorted comma-separated issue codes>` (for example `...:ledger_generation_invalid` or `...:candidate_path_git_state_mismatch`). Another bound file that no longer matches raises `incident_<binding name>_binding_invalid`.
   - Validation reopens every binding (changed manifest or owner-attestation bytes fail), recomputes every digest and nested projection (a changed path set, commit coordinate, raw message digest, nested binding type or normalized digest fails), permits later corrective commits that advance HEAD, and fails when the attempt files themselves drift.

3. Disposition `attempt_migration_disposition.v2` and its capture. `capture_invalidated_adopted(repository_root, *, incident_path, disposition_path, source_root, archive_root, governing_plan_path, migration_plan_path, authority_subject_path, authority_specification_review_path, authority_quality_review_path, intended_predecessor_head, restoration_commit, restoration_tree, expected_paths_manifest_path, protected_paths, generation5_request_path, generation5_snapshot_path, generation11_request_path, generation11_snapshot_path, live_ledger_path, baseline_path, baseline_specification_review_path, baseline_quality_review_path, workspace_baseline_path, attestation_request_path, attestation_snapshot_path, attestation_record_path) -> {"incident": ..., "disposition": ...}` builds the incident (item 2) and the disposition, publishes the incident first and then the disposition, each as its canonical JSON followed by `"\n"`, and returns both records.
   - The disposition keeps the v1 file, authority-review, repository-state, protected-path, row-set, archive-set, ledger-lineage and normalized-digest contracts. Keys, exactly: `schema_version` (`attempt_migration_disposition.v2`), `disposition` (`archive_invalidated_owner_adopted_uncommitted_attempt_and_restore_tracked_files`), `governing_plan_binding`, `migration_plan_binding`, `authority_review_bindings`, `attempt_binding`, `attempt_lifecycle`, `pre_move_repository_state` (equal to the incident's), `protected_path_bindings`, `ledger_lineage`, `attempt_rows`, `attempt_path_count`, `attempt_path_set_sha256`, `archive_path_set_sha256`, `normalized_row_set_sha256`, `normalized_disposition_sha256`, `claims_not_made`.
   - `attempt_lifecycle` = `{"adoption_state": "owner_adopted", "repository_commit_state": "uncommitted", "invalidation_reason": "workspace_baseline_predecessor_mismatch", "incident_binding": <file binding of the incident>, "workspace_baseline_role": "workspace_baseline", "owner_attestation_role": "attestation_record", "adoption_transfer": "forbidden"}`.
   - `attempt_binding.artifact_bindings` has exactly the roles `baseline`, `baseline_specification_review`, `baseline_quality_review`, `workspace_baseline`, `attestation_request`, `attestation_snapshot`, `attestation_record`, each bound as `{"path", "file_type", "lstat_mode", "size", "sha256"}` equal to that file's attempt row; `attestation_snapshot` is the original pending bytes and `attestation_record` the owner-confirmed record (both content-addressed).
   - `claims_not_made` = `["The captured attempt was personally owner-adopted but remained uncommitted when its repository predecessor was invalidated.", "Historical owner adoption remains bound only to the archived attempt and may not be transferred to or consumed by any later attestation, index, or completion claim.", "Archival relocation preserves bytes but grants no mutation or completion authority.", "A later attempt may begin only after the tracked live file equals its reviewed restoration binding."]`.
   - Capture fails (raises `AttemptMigrationError`, and the disposition is not written) on any extra or missing attempt path, a malformed or non-owner-confirmed owner record, a changed incident coordinate, ambiguous ancestry, a covered-only predecessor delta, protected-path drift, or a ledger-restoration mismatch.
   - Replay: when both outputs exist and equal what capture derives, capture returns the same result and changes nothing (repository status included). When the exact incident exists and the disposition does not (a crash between the two publications), capture completes only if the repository state equals the incident's `pre_move_repository_state` apart from the incident file itself, which must be the sole new untracked path. Every other state fails: a disposition without its incident, a different (even by one byte) incident or disposition, or an incident output path that is tracked, staged, part of a rename, or crosses outside its directory.
   - CLI: `python -m orchestrator.retirement.attempt_migration capture-invalidated-adopted --repository-root R` plus one `--<option>` per keyword above (underscores as hyphens, for example `--incident-path`, `--generation5-request-path`, `--attestation-record-path`) and `--protected-path P` repeated per protected path. On success it prints `{"incident": ..., "disposition": ...}` as JSON on standard output, nothing on standard error, and exits 0; on `AttemptMigrationError` it prints the error to standard error and exits 1.

4. Schema dispatch, apply and postvalidation. `validate`, `apply` and `postvalidate` dispatch strictly on `schema_version`: v1 goes through the unchanged v1 path, v2 through its own rules, unknown versions fail. A v2 record that substitutes v1 fields (for example the v1 artifact roles, or no `attempt_lifecycle`) fails. V2 validation reopens the incident, attestations, workspace baseline, reviews, Git objects, attempt rows, protected paths and ledger lineage. Apply stays gated on the exact disposition and its ordered reviews committed at HEAD; it archives every enumerated file under `archive_root` byte- and mode-exactly, removes only enumerated untracked sources and restores only the tracked live ledger; replay accepts only the exact pre-state or the exact completed post-state. In the completed post-state `validate` still returns the disposition, `apply` replays without change, and `postvalidate` writes a report with `result: "passed"` and a `disposition_binding` naming the disposition path.

5. Post-archive logical view. After relocation, v2 validation re-derives the archived evidence through a logical view built from the disposition rows: each mapped original path reads the exact row-bound source or archive bytes (shadowing live or restored bytes at the same path; the archived attempted ledger shadows the restored live ledger); an unmapped path may read live bytes only when it is a regular file in HEAD whose current bytes equal the HEAD blob; a missing, ambiguous or byte/mode-inexact mapped path fails. Candidate identity, status, ancestry and other Git-derived checks still read the real repository. Through this view the post-archive validation rejects: a missing materialization request or snapshot row (`attempt_row_state_invalid`); a generation-11 request or snapshot whose bytes are rebound in the archive so that it is swapped with the other, duplicates the request bytes, is noncontiguous, or names a wrong-parent prior request or snapshot (`semantic_coordinate_row_binding_mismatch:<role>`, the role being `generation11_snapshot` for a duplicated snapshot and `generation11_request` otherwise); a committed duplicate generation slot (`incident_known_failure_baseline_binding_invalid:...ledger_generation_invalid...`); candidate-path Git-state drift (`incident_known_failure_baseline_binding_invalid:...candidate_path_git_state_mismatch...`); nested broad-evidence tamper that is internally rebound (`incident_<...>_binding_invalid`); a new path outside the status projection, or index/status drift of candidate paths (`outside_status_projection_changed`); repository ancestry that does not descend from the captured HEAD (`capture_head_not_ancestor`).

6. Byte overlays for the existing validators. `orchestrator.retirement.materialization.validate_generation(repository_root, request_path, snapshot_path, *, bound_file_bytes=None, require_committed_fallback=False)` and `orchestrator.retirement.broad_evidence.validate_bound_record(..., bound_file_bytes=None, require_committed_fallback=False, ...)` (and the review-pair and review-subject validators that feed them) accept a mapping from repository-relative path to bytes. With an overlay, every bound file and every earlier generation in the lineage is read from the overlay when present; the same lineage checks and issue codes apply to the overlay bytes: issue `prior_generation_invalid` with message `prior_generation_changed` for a missing or swapped ancestor request/snapshot, `request_prior_generation_invalid` for a noncontiguous ancestor, `request_path_mismatch` / `snapshot_path_mismatch` for an ancestor under the wrong parent, `generation_request_slot_extra` / `generation_snapshot_slot_extra` for a mapped duplicate slot alongside the live one, and `ledger_completion_review_pair_invalid` when a review pair replayed from the overlay changed. A completed ledger generation whose closing subject and reviews are present only in the overlay (their live bytes invalid) validates. With `require_committed_fallback=True`, a path absent from the overlay may fall back to the live file only when it is a regular file committed at HEAD with identical current bytes; otherwise the review binding reports `review_binding_immutable_unreadable`.

7. Public surface. `orchestrator.retirement.__all__` additionally exports `derive_committed_predecessor_lineage` and `validate_attempt_migration_incident`, still imported lazily: importing `orchestrator.retirement` loads no submodule. The `--help` subcommand sets of `python -m orchestrator.retirement.broad_evidence` and `python -m orchestrator.retirement.source_bindings` are unchanged.

Constraints. No runtime, workflow, Workflow Lisp or provider behaviour changes; these are repository evidence tools only. No new third-party dependency. Tests are behavioural and use temporary Git repositories; no test asserts prompt prose.

Literals checked by acceptance tests: the schema versions, disposition value, lifecycle values, artifact roles, claims texts and key sets above; error codes `incident_owner_lifecycle_invalid`, `semantic_coordinate_row_binding_mismatch:<role>`, `incident_known_failure_baseline_binding_invalid`, `incident_<binding>_binding_invalid`, `attempt_row_state_invalid`, `outside_status_projection_changed`, `capture_head_not_ancestor`, `ledger_generation_invalid`, `candidate_path_git_state_mismatch`, `candidate_path_set_live_mismatch`; issue codes and messages `prior_generation_invalid`, `prior_generation_changed`, `request_prior_generation_invalid`, `request_path_mismatch`, `snapshot_path_mismatch`, `generation_request_slot_extra`, `generation_snapshot_slot_extra`, `ledger_completion_review_pair_invalid`, `review_binding_immutable_unreadable`; the CLI subcommand `capture-invalidated-adopted`; `result: "passed"`.

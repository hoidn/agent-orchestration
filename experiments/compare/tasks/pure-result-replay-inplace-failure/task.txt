Add a derived pure-result persistence profile: under it, a run stores each eligible compiler-generated pure projection's success as an exact value-free completion shell, and resume reconstructs the needed pure values from durable inputs in memory instead of reading persisted pure results, bundles or pure checkpoints.

What it is for. Compiler-generated `pure_projection` steps of Workflow Lisp programs are deterministic functions of earlier durable results and bound inputs. Today each one persists its full value row, a result bundle and lexical-checkpoint authority, so state grows with derived data and resume trusts copies of values that could be recomputed. The profile records only that an eligible pure step completed, and resume re-derives those values without effects or writes.

Required behaviour.

1. The profile selector.
   - `RunState` (`orchestrator.state`) gains an optional field `result_persistence_profile`, which may be set by keyword at construction. Absent means the historical bundle-backed persistence; `to_dict()` then omits the key, and `from_dict()` of a payload without it gives None and round-trips unchanged.
   - The only supported present value is `derived_pure_replay.v1`. Any other value fails closed with a `ValueError` whose message mentions the profile: at `RunState` construction, at `StateManager.initialize(...)`, and on load from disk. A load failure leaves the state file byte-for-byte unchanged.
   - `StateManager.initialize(workflow_file, context=None, bound_inputs=None, observability=None, result_persistence_profile=None)` writes the field atomically when the run state is created, before any visit. Generic `initialize` callers stay explicit opt-in; ordinary loads never infer, backfill or upgrade the field.
   - Automatic selection: a successfully compiled typed public `.orc` run (`orchestrator run`) and a new `.orc` root created by `orchestrator resume --force-restart` select `derived_pure_replay.v1`. The force-restart source run is left byte-for-byte unchanged, and the new root keeps the requested observability settings.
   - A fresh non-iterative child call frame whose callee bundle has the validated provenance `frontend_kind == "workflow_lisp"` also selects the profile. The selection comes from the callee's typed provenance, never from the parent's profile, a path suffix, an alias or a step identity. When a fresh retry is required outside the qualified in-place recovery of item 4, it is new state and selects the profile; the failed predecessor stays unchanged. The qualified route instead restores the same existing frame and never upgrades its profile.
   - Existing roots and frames keep their persisted profile, including absence of the field; non-Workflow-Lisp callees and iteration-owned child frames keep the historical profile. An existing frame is never backfilled or upgraded to qualify for recovery. A malformed existing frame (no `state`, or a `state` that is not a mapping) is rejected with a `ValueError` mentioning `existing call-frame state` before anything is written.
   - `orchestrator.workflow.call_frame_state.load_existing_call_frame_read_only(existing_frame)` returns that frame's state as a detached copy, without creating directories or writing anything.

2. Eligibility and the replay index. `orchestrator.workflow.pure_result_replay.derive_pure_result_replay_index(bundle, *, scope_kind="root") -> PureResultReplayIndex` derives, without mutating or serializing the program, which pure nodes are replay-eligible and what each depends on.
   - Eligible means a compiler-generated `pure_projection` that is acyclic and visited at most once per scope. Recurrent, loop-owned and other multiply visited pure nodes are not eligible; they keep their full durable rows, bundles and checkpoints even inside a profiled root. `ineligible_pure_reasons[node_id]` records why, for example `multiple_visit_region`.
   - `PureResultReplayIndex` has `scope_kind`, `nodes` (node id -> node), `topological_node_ids`, `ineligible_pure_reasons` and `required_pure_node_ids(seed_addresses, *, reached_node_ids) -> tuple[str, ...]`, the pure nodes needed to rebuild the given result addresses.
   - Each node has `node_id`, `step_id`, `presentation_key`, `bindings` (each with a `path` and a typed `address`), `output_addresses`, `output_contracts`, `pure_dependency_node_ids` and `durable_dependency_node_ids`.
   - Binding value documents may hold exact `{"ref": ...}` leaves and ordinary literal leaves. Only exact refs form dependency edges. Every literal subtree must match its declared binding type, including the inactive members of union literals; a wrong-typed literal or a malformed ref object fails.
   - Refs are scoped to the workflow that holds them. An imported callee bundle indexes only its own nodes, under its own scope `"root"`. `scope_kind` must match the bundle's actual scope; a mismatch raises `dependency_index_invalid` with `context["expected_scope"]` and `context["actual_scope"]`.
   - The derived index never changes the serialized runtime plan.
   - `PureResultReplayIndexError(reason, message, *, context=None)` is a `ValueError` with `.code == "pure_result_replay_unavailable"`, `.reason` and `.context`. Reasons include `dependency_index_invalid` (a cycle, a duplicate projection authority, a projection identity mismatch, unbound text, a cross-frame ref, wrong literal types), `reachability_ambiguous`, `multiple_visit_region`, `progress_witness_invalid` and `profile_conflict`.

3. The value-free completion shell and visit atomicity.
   - `PureReplayVisitWitness(presentation_key, step_index, step_id, visit_count)` identifies one single-visit pure execution.
   - `build_pure_completion_shell(witness)` returns exactly `{"name": <presentation_key>, "step_id": <step_id>, "visit_count": 1, "status": "completed", "exit_code": 0, "outcome": {"status": "completed", "phase": "execution", "class": "completed", "retryable": false}, "result_storage": "derived_pure_replay.v1"}`, built directly rather than by serializing a step result.
   - `validate_pure_completion_shell(row, *, witness)` raises `ValueError` for any other row: an extra key (for example `value`, `output`, `text`, `json`, `artifacts`, `debug`, `duration_ms`, `output_bundle`), a missing key, a wrong value, or an outcome that is not exactly the one above.
   - Failed and skipped rows stay full durable rows.
   - `StateManager` methods, each one atomic state transaction:
     - `begin_eligible_pure_visit(*, step_name, step_index, step_id) -> int` increments the visit and publishes the matching running cursor `current_step` = `{"name", "index", "type": "pure_projection", "step_id", "visit_count", "status": "running", "started_at", "last_heartbeat_at"}`; it returns the visit count.
     - `reuse_interrupted_eligible_pure_visit(witness) -> int` validates an interrupted visit with its matching cursor and returns the same visit count without writing.
     - `settle_eligible_pure_success(witness)` persists and returns the exact shell and clears the cursor.
     - `settle_eligible_pure_failure(witness, result)` persists the full failed or skipped `StepResult`, clears the cursor and returns None.
   - `OutcomeRecorder.persist_step_result(..., eligible_pure_settlement=witness)`: on success it settles through the state manager's `settle_eligible_pure_success(witness)` instead of an ordinary step update, keeps the full finalized result (with its artifacts) in the in-memory `state["steps"]` and returns it, and passes the exact shell to the summary emitter. On failure or skip it settles the full row through `settle_eligible_pure_failure(witness, result)`.
   - `classify_pure_replay_progress(state, *, witness) -> str` classifies a state's visit, cursor and row for the witness:
     - `unstarted`: no visit, no cursor, no row; a running cursor of an unrelated step is allowed.
     - `interrupted`: visit and matching running cursor, no row.
     - `derived_complete`: visit and exact shell, with no cursor or an unrelated one.
     - `durable_failure_skip`: visit and a full failed or skipped row.
     - `progress_witness_invalid` for anything else: a visit without cursor or row; a cursor or shell without a visit; cursor plus row; a cursor or row whose visit count, step id, presentation key, index, type or status mismatch; a failure or skip with a mismatched visit or identity; a value-bearing completion; a non-terminal row; cursor plus failure.

4. Replay at resume. The replay runtime is `PureReplayRuntime(*, bundle, scope_path)`, where `scope_path` is the existing `ResumeScopePath`. Its index is `.index`, with `index.scope_kind == "root"` for a root scope. Methods:
   - `witness(node_id, *, visit_count=1)`, `witness_from_state(node_id, state)`;
   - `node_id_for_step_id(step_id)`: the eligible node a durable step id names, or None;
   - `record_full_result(node_id, *, witness, result)`: holds an active executor's validated full result in the process-local cache;
   - `replay_node(node_id, *, state, evaluate_node)`: evaluates one node with the given callable over the overlay;
   - `value_for_state_address(address, state)` and `resolve_state_address(address, state) -> (found, value)`;
   - `required_node_ids_for_boundary(restart_node_id, *, state)`;
   - `audit_boundary_leaves(restart_node_id, *, state)`;
   - `overlay_active_state(state) -> dict`;
   - `audit_persisted_surfaces(*, state, state_manager, resolve_bundle_path)`.
   - Replay validates only the required dependency leaves and reconstructs typed values into the overlay. It never dispatches an effect, increments a visit, settles a result or writes durable state.
   - A retained overlay row never overrides current state authority. Every cache hit revalidates the exact visit and must see either the exact durable shell or the exact validated active result held in the cache. The active-result form is valid only when `current_step` is absent or belongs to an unrelated node; a cursor targeting the same presentation name or step identity fails with `progress_witness_invalid`. Missing or non-one visits, missing or malformed rows and mismatched active rows also fail.
   - For a union pure result, the static catalog keeps every possible typed address, while the transient row holds exactly the discriminant, the shared outputs and the active variant's outputs. A missing active member or an extra inactive member is invalid (`dependency_index_invalid`); row presence, not presence of every union address, proves reconstruction.
   - A resumed run fails closed before any effect with `error.type` `pure_result_replay_unavailable` and `error.context.reason`:
     - `durable_input_missing` or `durable_input_invalid` for a missing or invalid bound input. A durable intrinsic of the wrong type (`exit_code`, or `outcome` `status`/`phase`/`class`/`retryable`) is also `durable_input_invalid`.
     - `binding_unresolved` (with `context.cause` `{"type": "materialize_ref_unresolved"}`), `evaluation_failed` (`{"type": "pure_evaluation_failed"}`) and `output_contract_invalid` (`{"type": "pure_projection_contract_invalid"}`) when re-deriving a value fails.
     - `progress_witness_invalid` for a visit-two cursor or a visit-two shell, rejected before the prologue.
   - On success, resume after an interruption between effects reproduces the same outputs and calls no committed effect again.
   - Known settled failures gain in-place recovery only under the exact persisted profile `derived_pure_replay.v1`. An ordinary command must use policy `reuse_validated_structured_output`. At a selected typed Workflow Lisp call, both the caller and selected callee must already persist exactly that profile, at every nested boundary. New-frame selection still follows item 1; resume never infers, backfills or upgrades an existing root/frame. Absent-profile historical frame selection and restoration remain unchanged.
   - Recovery requires a present, integral, matching node-local checkpoint with valid, restorable `restore_payload`, matching the exact current failed row's step identity and visit against `step_visits` and frame identity under the boundary's existing checkpoint convention: a call-boundary record identifies the selected callee frame, and a command record inside that callee identifies its containing frame. Validate these existing identities; never rewrite or backfill them. A later cursor, completed result or another row's, visit's or frame's checkpoint cannot substitute. Unknown/interrupted attempts do not qualify.
   - Restore the caller environment, reconstruct required pure values in the overlay, then retry the ordinary command or re-enter the call through `CallExecutor`; the resume selector never directly executes a callee. Call entry prefers the validated running lineage member; otherwise it resumes the latest validated failed member in the same frame, without a fresh retry or repetition of already committed inner effects. Reapply the exact caller/callee profile and checkpoint requirements at each nested boundary.
   - Preserve all existing checksum, authored-input, managed/runtime-input, write-root and resume-bound-input validation, projection/lineage audits, failed-predecessor validation and diagnostic precedence. Failed members remain fully validated, including the member chosen for in-place recovery. Missing, invalid or non-restorable checkpoint authority retains the existing fail-closed barriers. Unknown/interrupted attempts do not satisfy this settled-failure exception; existing interruption routes and their barriers remain unchanged. Other policy/effect categories, provider recovery, certified adapters, groups and transitions are unchanged.
   - Each run creates its provider observation manager when execution starts, not when the executor is constructed, and closes it once at the end; no manager is created when observation is disabled.
   - A resume determines the restart boundary once: exactly one call of `ResumePlanner.determine_restart_node_id`. That node is passed on: `ResumePlanner.determine_default_resume_decision(..., restart_node_id=...)` takes it as a keyword.

5. Durable surfaces under the profile.
   - A clean profiled run leaves eligible pure results value-free outside the active overlay. There are no value rows, no pure result bundles and no private lineage (`private_artifact_versions` entries) for them, and the run's `workflow_outputs` are unchanged. Checkpoint records are still written for effect boundaries, but none has `pending_effect_policy.effect_kind` `pure_projection`, and no restore binding takes its `source_step_id` from an eligible pure step.
   - A persisted value row, pure bundle or private-lineage entry for an eligible node is a conflict: `PureResultReplayIndexError` with reason `profile_conflict` and `context["surface"]` `steps`, `pure_bundle` or `private_artifact_versions` respectively. It is raised before the prologue or any state write.
   - An eligible node's checkpoint record or restore binding in the same scope is also a conflict, with `context["surface"]` `checkpoint_record` or `restore_payload`. Noneligible recurrent records and records of other frames are allowed.
   - Replay-eligible pure points are filtered out of the durable checkpoint candidates before unique-nearest selection: they emit no checkpoint record, and their payload omits derivable pure bindings. Historical and noneligible points keep their policy, and an unstarted eligible point keeps node-local checkpoint authority.
   - Default resume (`orchestrator.workflow_lisp.lexical_checkpoint_default_resume.determine_runtime_default_resume_decision`) admits exactly one zero-record case: `restore_decision` `VALIDATED_FRAME_ENTRY_REPLAY`, with `mode` `LEXICAL_CHECKPOINT_DEFAULT`, `checkpoint_id` null and `selection_reason` `validated_frame_entry_replay`. It requires validated bound-input leaves and exact profile and progress witnesses, and without a durable owner it fails closed (`mode` `FAIL_CLOSED`, diagnostics `["lexical_default_resume_prior_boundary_not_restorable"]`).
   - Settled-failure recovery in item 4 uses the matching durable node-local checkpoint, never `VALIDATED_FRAME_ENTRY_REPLAY`; it creates no second zero-record exception and never accepts absent, invalid or non-restorable authority. Eligible pure results remain exact value-free shells and are reconstructed only in the overlay. A failed effect boundary may restore earlier durable values, but it must not persist a derived pure value, pure bundle, eligible pure checkpoint or restore binding sourced from an eligible pure step.
   - Filtering never lets selection scan past an invalid nearest durable boundary. A restorable nearest noneligible point gives `selection_reason` `validated_prior_boundary`; a non-restorable one fails closed as above.
   - The durable step identity of a replayed node is distinct from its node id: `node_id_for_step_id` maps the durable id, and a raw node id maps to None.

6. Importable names. Acceptance tests import from `orchestrator.workflow.pure_result_replay`:
   - the constants `DERIVED_PURE_REPLAY_PROFILE` (`"derived_pure_replay.v1"`), `DEPENDENCY_INDEX_INVALID` (`"dependency_index_invalid"`) and `MULTIPLE_VISIT_REGION` (`"multiple_visit_region"`);
   - every class and function named above;
   - a module-level callable named `_propagate_pure_ineligibility`, whose behaviour is not checked.

Constraints. State schema stays `2.1`; the profile field is additive. The historical absent-profile behaviour, including frame selection and restoration, does not change. In-place settled-failure recovery is limited to the exact-profile cases in item 4 and does not upgrade existing state or relax any other recovery policy or barrier. No new third-party dependency. Tests are behavioural; no test asserts prompt text. Documentation: the profile contract in `specs/state.md`.

Literals checked by acceptance tests: `derived_pure_replay.v1`, `result_persistence_profile`, `result_storage`, the shell above, `pure_projection`, `unstarted`, `interrupted`, `derived_complete`, `durable_failure_skip`, `progress_witness_invalid`, `pure_result_replay_unavailable`, `dependency_index_invalid`, `reachability_ambiguous`, `multiple_visit_region`, `profile_conflict`, `durable_input_missing`, `durable_input_invalid`, `binding_unresolved`, `evaluation_failed`, `output_contract_invalid`, `materialize_ref_unresolved`, `pure_evaluation_failed`, `pure_projection_contract_invalid`, `steps`, `pure_bundle`, `private_artifact_versions`, `checkpoint_record`, `restore_payload`, `VALIDATED_FRAME_ENTRY_REPLAY`, `validated_frame_entry_replay`, `validated_prior_boundary`, `LEXICAL_CHECKPOINT_DEFAULT`, `FAIL_CLOSED`, `lexical_default_resume_prior_boundary_not_restorable`, `existing call-frame state`.

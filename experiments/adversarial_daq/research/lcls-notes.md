# LCLS-II DAQ evidence and candidate benchmark cases

Research snapshot: 2026-10-22/23. Public primary sources only. No operational DAQ commands were executed. This is evidence for a synthetic benchmark, not an operations procedure or proof that a production fault was reproduced.

## Findings that should constrain both adversaries

The broad claim that Python-based SLAC graphs cannot catch incompatible connections before expensive execution is already contradicted by AMI. The SLAC-authored ICALEPCS2025 paper describes mypy checks when users connect nodes, graph compilation with NetworkFoX, and runtime monitoring of latency, throughput, heartbeat completion and pruning. Its heartbeat recovery intentionally publishes partial results and drops late contributions: a missing monitoring contribution is not automatically lost recorded science data. The paper also documents EPICS export into Bluesky/XOpt. This is a particularly relevant baseline for the skeptical audience. [AMI paper, pp. 1–5](https://proceedings.jacow.org/icalepcs2025/pdf/THAG005.pdf)

Existing DAQ control is itself a dependency-aware state machine. It uses the Python `transitions` package, validates requested state changes, restricts record/config changes by state, and correlates client responses with transition message IDs. Configure has distinct configuration and timing phases. A missing active-detector file raises an error but switches to bypass/default behavior; it does **not** invariably block allocation. Allocation requires DRP and TEB participation, while missing MEB warns about AMI support. The source thus supplies both existing defenses and real policy choices a benchmark can exercise. [Control implementation, lines 837–870, 1142–1215, 1295–1350, 1817–1854, 2223–2371](https://github.com/slac-lcls/lcls2/blob/04d36d15c222ec6dbc10b833bf0c3ef5059a5c34/psdaq/psdaq/control/control.py)

`pcdsdaq.DaqLCLS2` already offers asynchronous status objects for states/transitions, configuration validation, timeouts, and reconfiguration when a different controller has configured the DAQ. It is a serious comparison component, not a straw-man loose script. [DaqLCLS2, especially `_get_status_for`, `preconfig`, `configure`](https://github.com/pcdshub/pcdsdaq/blob/4a3f2504b4d6f1860457ecfc40aaaf28115a777f/pcdsdaq/daq/lcls2.py)

## Eight candidate cases

The mutations, costs, accepted recoveries, and provenance guards below are benchmark proposals. Source citations establish the relevant mechanism; they do not establish the proposed simulated incident occurred. Use hidden variants with the same visible symptom and different root causes. Both implementations must receive identical observations and permitted actions.

| Case | Evidence and realistic observations | Proposed test and minimally disruptive success condition | Strong counterexample / confounder |
|---|---|---|---|
| 1. Incompatible data contract before acquisition | AMI checks graph connections with mypy. DAQ typed JSON helpers validate supported scalar types, ranges, and array dtype/shape. [AMI](https://proceedings.jacow.org/icalepcs2025/pdf/THAG005.pdf), [typed JSON](https://github.com/slac-lcls/lcls2/blob/04d36d15c222ec6dbc10b833bf0c3ef5059a5c34/psdaq/psdaq/configdb/typed_json.py) | Supply a known producer/consumer mismatch before a simulated costly dark run, then separately inject malformed external JSON after execution starts. Require preflight rejection for the first; boundary validation and useful diagnosis for the second. | Existing mypy plus schema validation can reject the first too. Static contracts cannot prove arbitrary future JSON valid. Count wasted acquisitions and contract-authoring effort; do not claim all runtime parsing can be eliminated. |
| 2. Configure request accepted, timing phase incomplete | DAQ configure waits for phase-one client answers, then inserts a timing transition and waits for phase-two replies. [Control, `condition_configure`](https://github.com/slac-lcls/lcls2/blob/04d36d15c222ec6dbc10b833bf0c3ef5059a5c34/psdaq/psdaq/control/control.py) | Emit an acknowledgment but withhold one phase-two contribution. Include transition ID, participating aliases, latest state and timeout diagnostics. Never mark configured based on request success alone; identify the missing participant, preserve evidence, and use only the simulator's targeted recovery. | DaqLCLS2 status objects already wait for state/transition completion. A Python callback or state predicate can express the constraint. A long transition is not necessarily permanent failure. |
| 3. Required detector missing or duplicated at rollcall | Control tracks active aliases and warns about missing participants; duplicate aliases are reported. Missing selection file enables defaults/bypass. [Control, `condition_rollcall`](https://github.com/slac-lcls/lcls2/blob/04d36d15c222ec6dbc10b833bf0c3ef5059a5c34/psdaq/psdaq/control/control.py) | Remove a required alias, duplicate one under another process, or remove the selection file. Require discovery against an explicit experiment manifest and refuse a scientifically incomplete run even if the simulated control state advances. Restore only the intended configuration/process. | “Running” alone does not certify the intended detector set. Manifest validation is conventional Python; default/bypass may be deliberate during commissioning. Avoid rewarding blanket refusal of all changed topologies. |
| 4. File prefix exists but data are not ready | DRP names files with experiment, run, stream and chunk components and writes both XTC2 and SMD XTC2. The current psana reader distinguishes observed `.xtc2.inprogress` transfers from live FFB writes and waits for configuration/run metadata. [DRP file handling](https://github.com/slac-lcls/lcls2/blob/04d36d15c222ec6dbc10b833bf0c3ef5059a5c34/psdaq/drp/DrpBase.cc), [SMD reader](https://github.com/slac-lcls/lcls2/blob/04d36d15c222ec6dbc10b833bf0c3ef5059a5c34/psana/psana/psexp/smdreader_manager.py) | Present a wrong-run prefix match, missing stream, partially transferred file, or already complete offline replay. Require identity, completeness and metadata checks before analysis; bounded wait if completion is still expected. | A file sensor plus manifest/parser can do this. Existing psana handles important readiness cases. Never equate filename existence, newest mtime, transfer completion and EndRun; they are different facts. |
| 5. Calibration is newer but belongs to the wrong data | Current calibration lookup includes detector, experiment, calibration type, run/time and version; explicit run-range selection is implemented. [Calibration lookup](https://github.com/slac-lcls/lcls2/blob/04d36d15c222ec6dbc10b833bf0c3ef5059a5c34/psana/psana/pscalib/calib/MDBWebUtils.py) | Give the agent a newer wrong-detector/invalid-run constant and an older valid one; then modify the simulated detector configuration after a derived product was created. Check semantic provenance and invalidate only affected products. Content hashes/configuration generations are proposed simulator fields. | Real calibration validity is not “B newer than A.” Existing calibration APIs handle run validity; Make-style timestamps alone are insufficient for both competitors. Measure correctness with preserved/copied mtimes and clock skew. |
| 6. Frozen AMI display versus stalled acquisition | AMI exposes completion/pruning metrics; a June 2024 MFX operator guide distinguishes AMI and DAQ restarts. Control warns if no MEB is present. [AMI](https://proceedings.jacow.org/icalepcs2025/pdf/THAG005.pdf), [MFX guide](https://s3df.slac.stanford.edu/data/lcls/mfx/Operators_Guide.html) | Same frozen plot, alternate causes: worker lag, absent monitoring path, or genuine acquisition stall. Compare current event/file growth, timestamps and monitoring metrics. Repair the affected simulated monitoring component when recording is healthy. | Low rate and heartbeat pruning can make apparently sparse monitoring normal. Penalize unnecessary full restarts and interrupted healthy runs. The guide is older, instrument-specific practice, not current universal LCLS-II policy. |
| 7. Storage open failure versus missing beam | DRP emits file-open diagnostics, reports separate raw/SMD open failures, and notes filesystem hangs are difficult to timeout/detect. Damage flags distinguish missing, timed-out, corrupted, out-of-order and other conditions. [DRP](https://github.com/slac-lcls/lcls2/blob/04d36d15c222ec6dbc10b833bf0c3ef5059a5c34/psdaq/drp/DrpBase.cc), [damage definitions](https://github.com/slac-lcls/lcls2/blob/04d36d15c222ec6dbc10b833bf0c3ef5059a5c34/xtcdata/xtcdata/xtc/Damage.hh) | Keep the visible event count flat while varying run mode, filesystem health and contribution damage. Require diagnostic narrowing before action; do not repeatedly start recording runs or change trigger settings to treat a storage error. | No file may be correct for a nonrecording run. A generic damage count is not a diagnosis. Avoid asserting that all storage hangs are recoverable by the agent. |
| 8. Historical shutdown crash mistaken for a live fault | Issue 134 reports epix100 DRP double-free symptoms on operator TERM shutdown; its author distinguishes observations from an unconfirmed common-cause hypothesis. Created 2026-09-29; updated 2026-10-15. [Issue 134](https://github.com/slac-lcls/lcls2/issues/134) | Mix an old-session teardown error with a current healthy run, then a variant with a current crash. Require host/process/session/time association, evidence preservation and honest escalation of an unresolved code defect. | Log-pattern matching alone creates false incidents. Do not invent a known fix or call the issue a confirmed root cause. This is an issue report, not a validated recovery procedure. |

## Diagnostics and recovery design

Capture observations before mutation: state and transition, active aliases/readout groups, recording mode, experiment/run, configuration identity, process generation, time-tagged counters, damage categories, recent per-process logs, and raw/SMD file identities. Process log collection is already provided by the DAQ Slurm tooling; its README documents configurable log roots. [DAQ Slurm README](https://github.com/slac-lcls/lcls2/blob/04d36d15c222ec6dbc10b833bf0c3ef5059a5c34/psdaq/psdaq/slurm/readme.md)

A recovery is successful only when the original acquisition/analysis objective is restored and independently checked. Restarting processes or returning a successful tool exit code is insufficient. The current MFX API documents restart interruption, reconnection and configuration considerations, followed by detector checks and a short validation run. These consequences motivate a simulator cost for disruption; they are not authorization to run those operations on real hardware. [MFX restart documentation](https://pcdshub.github.io/mfx/mfx/beamline.html)

Proposed benchmark metrics: correct diagnosis/action, incorrect success claims, expensive actions before failed prerequisites, irrelevant or excessive restarts, recovery cost, bounded waits, invalidated/reused artifacts, surviving a process restart, and implementation/maintenance burden. Include clean cases and unresolvable cases. Compare equal typed adapters, models, token/time budgets, diagnostics, seeded incidents and retry limits. Expose the difference between orchestration capability, default library behavior and amount of custom glue. A finite test suite can support a scoped practical advantage or parity finding; it cannot prove universal impossibility of a competing implementation.

## Scope and limitations

- [LCLS-II ECS paper (ICALEPCS2023)](https://epaper.kek.jp/icalepcs2023/papers/th2bco03.pdf) supports established IOC management, shared logs, git-tracked configuration and ongoing startup-script linting. Do not depict SLAC as having no diagnostics or deployment tools.
- [ExaFEL paper, published 2024-10-03](https://www.frontiersin.org/journals/high-performance-computing/articles/10.3389/fhpcp.2024.1414569/full) supports the newer XTC2/psana-II data path and the distinction between live/nearline storage and later analysis. Older forecasts about DAQ writing HDF5 should not override current source evidence.
- The [MFX operator guide](https://s3df.slac.stanford.edu/data/lcls/mfx/Operators_Guide.html) explicitly says last revised June 2024. The AMI paper is ICALEPCS2025. Search-engine crawl times were not treated as publication dates.
- The [Confluence finite-state-machine URL linked by DaqLCLS2](https://confluence.slac.stanford.edu/display/PSDMInternal/Finite+State+Machine) is an internal documentation pointer, not material read in this research. Attempts to retrieve public-looking LCLSIIData DAQ pages failed through the browser tool; no assertions are attributed to their unseen contents.
- Public sources do not establish fault incidence, operator-approved universal recovery sequences, or a production risk model. Those require a DAQ expert. Synthetic operation costs, lineage tokens, fault combinations and accepted repairs must be labeled as benchmark design assumptions and reviewed by the skeptic.

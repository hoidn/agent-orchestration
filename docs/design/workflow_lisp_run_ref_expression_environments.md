## Summary

Extend `run-ref` with a third program locus, `:program (:workflow <static-workflow-name>)`, whose child is a named workflow of the parent module graph, compiled by the ordinary closed-program pipeline as a private child entry. Each invocation materializes a pinned project revision, runs the child through the ordinary evaluated runtime inside a confined environment, and returns a typed outcome: the existing `value`, `workspace_delta`, and `accounting` envelope on completion, or a typed failure the parent can match on. Generating candidates, testing them, and selecting a result remain ordinary ORC composition.

The confinement substrate is the **existing rootless Bubblewrap backend**, extended as a sibling profile `run_ref_confinement.v1`: the rootfs is imported from a digest-pinned image into a sealed snapshot, the network namespace is unshared, cgroup v2 limits bound the child's processes, and every command and tool-enabled provider process of the child runs as a gated leaf inside one holder sandbox per child attempt. The host clone on disk stays the durable workspace; the sandbox executes a checkpointed copy. An inference gateway grants bounded access to the selected remote model without exposing host credentials or host tools. This is a proposed, separately versioned security profile, not a claim that current `run-ref`, provider defaults, or the existing provider-isolation profile already supply this behavior. The approach removes workflow-owned clone/setup scripts and avoids a second evaluator, coordinator or container engine, and it makes ambient dependencies and arbitrary network access harder by construction: dependencies must be in the image and networking is explicit.

## Problem, Goals, And Non-Goals

The current child form cannot express a normal agent-edit/test workflow in a cloned workspace. Authors move clone preparation into shell commands or manual harnesses, and then must invent workspace identity, dependencies, cleanup, and result ownership. A directory change alone cannot safely admit a tool-enabled coding agent. The required flow is: take a pinned revision and candidate count; create independent pinned workspaces without workflow-owned provisioning scripts; run a named workflow containing ordinary provider calls, commands, calls, branches, and finite loops; obtain a typed candidate outcome and durable exported files; choose the best result in the parent; resume without replaying committed child work.

Non-goals are an optimizer/search engine, population/fitness primitives, automatic promotion, mutable workspace handles, a container-engine framework, source-string evaluation, runtime closures, dynamic imports, arbitrary setup hooks, package installation during a run, remote worker scheduling, and unrestricted networking. Generated project code may be executed by commands inside the confined environment; generated ORC is not admitted as executing workflow code by this feature.

## Decisions And Alternatives

**D1, substrate.** The existing rootless Bubblewrap backend (`bubblewrap.v1`; launch in `isolation_bubblewrap.py`; cgroup v2 containment slots; result broker) is the substrate of a new sibling profile `run_ref_confinement.v1`. Reason: it is installed on the reference host, reviewed, FD-bound at the root authority (`specs/security.md:38`) and rootless without setuid helpers, which security excludes for v1. It makes harder: image distribution has no engine, so the runtime imports images itself; supplementary-group dropping stays at what the existing profile proves; every new control is implemented and qualified in this repository. The `:image` operand stays a digest-pinned OCI image, but the runtime **imports** it into a content-addressed sealed rootfs snapshot through the existing snapshot assembly rules (closed canonical manifest, descriptor-relative, fixed-zero-atime); no container engine runs it. Stop condition: F3 passed on 2026-10-14 (network, limits, quota, rootfs, commands, escapes and cleanup enforced) and returned deltas D-a to D-h, decided in the table below; Podman remains the recorded fallback only if F3b shows a leaf reaching the holder's channels or descriptors, an undetected slot escape, or a limit set as a unit property that is not enforced, with the measurements.

What the existing profile cannot do today, and what the sibling profile adds: `--unshare-net` (absent from today's argv; `:none` and `:model-only` both require it); cgroup v2 `memory.max`, `pids.max` and `cpu.max` on a per-attempt delegated scope (D-a); a rootfs taken from the imported image instead of the host provider closure; workflow commands admitted (today rejected); a workspace quota through a size-bounded tmpfs inside one holder sandbox per child attempt, checkpointed to the host clone after every leaf (D-b, D-f); and public run/resume integration, which is still pending for the provider profile ([capability matrix](../capability_status_matrix.md), provider-phase isolation row).

## Authored Contract

`:program` accepts exactly one of `(:path ...)`, `(:workflow <name>)`; `:bundle` remains refused. For a workflow child:

```lisp
(run-ref
  :source (:repo "file:///srv/project.git" :commit revision)
  :program (:workflow candidate-body)
  :inputs (:task task :variant variant)
  :policy (:environment :confined
           :image "registry.example/project@sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
           :network :model-only
           :limits (:wall-seconds 900 :memory-mib 4096 :cpus 2 :pids 256 :workspace-mib 2048 :output-mib 64)))
```

Image and limits are static literals. `:network` is exactly `:none` or `:model-only`; it never means general internet access. `:network :none` with any provider effect in the child's transitive summary refuses at compile time. All limits are positive bounded integers; `:memory-mib` must be at least `:workspace-mib + 960` (the profile's scratch, `/dev/shm`, result and headroom constants, D-d), refused at compile time by the ordinary operand validation; installation maxima are checked at admission; `:cpus` is an integer quota; `:output-mib` bounds exports only; `:wall-seconds` is the child's cumulative budget for guest execution and the host-side work done for it (R3). The image must have a repository name and SHA-256 digest, without a mutable tag as authority; the imported snapshot digest and platform are recorded at admission. A digest alone does not promise bitwise deterministic computation or model responses.

**D4, source operands.** `:repo` stays a compile-time literal canonical locator exactly as today. Only `:commit` becomes a pure `String` expression, evaluated once in the parent in authored order before child allocation, validated as a 40-hex SHA, and included in the effect input digest. A changed revision is ordinary resume input drift; a repeated loop visit can select another validated revision. Reason: the locator is deployment configuration; the revision is search state. It makes harder: choosing among repositories at run time needs separate sites. Path-mode literals do not change.

`:inputs` is explicit keyword/value data transport. Its expressions run once in the parent in authored order and bind by name to the child workflow's signature with its ordinary exact-arity and type checks. `ProcRef`, provider roles as values, Context/session values, resources and other authority-bearing values cannot cross. Typed path inputs are copied and validated, not host mounts. `:returns` is not accepted; the result type is derived from the child signature.

**D6, child failure as typed data.** For this profile the form's type is a compiler-owned per-site union: `(COMPLETED (result <envelope>))`, where the envelope keeps the three existing fields `value`, `workspace_delta` and `accounting` (validated by `orchestrator/workflow/run_ref/result_contract.py`), and `(FAILED (code String) (detail String) (accounting <same>))` for child runtime failure, wall-time/budget exhaustion, environment refusal after release and environment loss after release (holder death, R2). The parent matches on it; one failed candidate does not abort the search. Structural, compile and admission failures before release still abort the parent effect under ordinary EE rules. Reason: a search must survive a lost candidate without authoring a second failure union per site. It makes harder: callers must match; a bare `.value` access no longer typechecks. Exact spelling is fixed with the contract amendments.

### Complete candidate-generation and selection module

This is complete illustrative future syntax. Every form except `run-ref :program (:workflow ...)` and its `:policy` compiles today at target 2.36 (verified: a variant in which `one-candidate` reaches `candidate-body` through `call` and matches a stand-in union compiled with the public `compile` command, exit 0, two sites). `NEXT_RUN_REF_TARGET` denotes the unassigned target and must not be replaced with a current target. Deployment supplies the ordinary provider binding manifest, here `{"providers.coder":"codex_unrestricted_workspace","providers.judge":"codex_unrestricted_workspace"}`; those profiles' bypass flags disable only the CLI's inner sandbox, and the outer profile is the boundary. The shown digest is illustrative; the repository is a literal locator and the revision is a typed run input. There is no shell provisioning command.

```lisp
(workflow-lisp
  (:language "0.1")
  (:target-dsl "NEXT_RUN_REF_TARGET")
  (defmodule isolated_candidates)
  (export run)

  (defpath CandidateFile :kind relpath :under "artifacts" :must-exist true)
  (defrecord Candidate (file CandidateFile) (summary String))
  (defrecord Assessment (valid Bool) (score Float) (reason String))
  (defrecord CandidateResult
    (candidate Candidate) (assessment Assessment) (variant Int))
  (defunion CandidateOutcome
    (PRODUCED (result CandidateResult))
    (LOST (code String) (detail String)))
  (defrecord SearchState (best CandidateOutcome) (next Int))
  (defunion Selection
    (SELECTED (result CandidateResult))
    (INVALID (reason String)))

  (defprompt implement
    (:fills (task :text) (variant :value Int)) -> Candidate
    "Implement the project task in artifacts/candidate.py using the repository and the tools available here. Task: {task}. Candidate number: {variant}. Return the candidate file and a short summary.")

  (defprompt assess
    (:fills (task :text) (candidate :doc CandidateFile)) -> Assessment
    "Evaluate the injected candidate for this task: {task}. Use the project's tests and tools in this workspace. Return validity, a finite score where lower is better, and the reason for the score.")

  (defworkflow candidate-body ((task String) (variant Int)) -> CandidateResult
    (let* ((candidate
             (provider-result providers.coder
               :prompt (implement :task task :variant variant)))
           (assessment
             (provider-result providers.judge
               :prompt (assess :task task :candidate candidate.file))))
      (record CandidateResult :candidate candidate
        :assessment assessment :variant variant)))

  (defworkflow one-candidate
    ((revision String) (task String) (variant Int)) -> CandidateOutcome
    (let* ((child
             (run-ref
               :source (:repo "file:///srv/project.git" :commit revision)
               :program (:workflow candidate-body)
               :inputs (:task task :variant variant)
               :policy (:environment :confined
                        :image "registry.example/project@sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
                        :network :model-only
                        :limits (:wall-seconds 900 :memory-mib 4096 :cpus 2
                                 :pids 256 :workspace-mib 2048 :output-mib 64)))))
      (match child
        ((COMPLETED c)
          (variant CandidateOutcome PRODUCED :result c.result.value))
        ((FAILED f)
          (variant CandidateOutcome LOST :code f.code :detail f.detail)))))

  (defworkflow run
    ((revision String) (task String) (candidates Int :default 3)) -> Selection
    (if (or (< candidates 1) (> candidates 16))
      (variant Selection INVALID :reason "candidates must be between 1 and 16")
      (loop/recur
        :max 17
        :state (record SearchState
                 :best (variant CandidateOutcome LOST
                         :code "none" :detail "no candidate produced")
                 :next 0)
        :on-exhausted (variant Selection INVALID :reason "iteration limit")
        (fn (state)
          (if (>= state.next candidates)
            (done
              (match state.best
                ((PRODUCED p)
                  (if p.result.assessment.valid
                    (variant Selection SELECTED :result p.result)
                    (variant Selection INVALID :reason "no valid candidate")))
                ((LOST l) (variant Selection INVALID :reason l.detail))))
            (let* ((outcome
                     (call one-candidate :revision revision
                       :task task :variant state.next))
                   (best-beatable
                     (match state.best
                       ((LOST l) true)
                       ((PRODUCED b) (not b.result.assessment.valid))))
                   (best-score
                     (match state.best
                       ((LOST l) 0.0)
                       ((PRODUCED b) b.result.assessment.score)))
                   (better
                     (match outcome
                       ((LOST l) false)
                       ((PRODUCED p)
                         (and p.result.assessment.valid
                           (or best-beatable
                             (< p.result.assessment.score best-score))))))
                   (best (if better outcome state.best)))
              (continue
                (record SearchState :best best :next (+ state.next 1))))))))))
```

Each candidate gets a fresh clone. The two providers within that child share that clone and the holder's PID and IPC namespaces, while the host empties scratch (`/tmp`, HOME, `/dev/shm`) and `/result` between leaves and creates each attempt's result directory exclusively, so a leaf never sees another leaf's scratch, in an uninterrupted run or after a resume; only leaked SysV objects can differ, and no leaf may depend on them. The loop is serial and needs no parallel-map qualification. Ties keep the earlier result. A lost or invalid candidate leaves `best` unchanged, and `done` returns `INVALID` unless the best assessment is valid; the runtime never invents a successful candidate. The file returned to the parent is the exported `CandidateFile`, not a path into a live clone.

The judge is an ordinary provider with the candidate's trust level, not a sealed benchmark oracle. A research workflow still has to enforce the separate whole-candidate evidence and holdout rules in the program-search boundary. A deterministic checker can replace `assess` with an ordinary certified `command-result` installed in the immutable image, but candidate code loaded in the same process/UID can tamper with execution or forge the result channel. Such scores remain child-produced evidence unless a separately reviewed evaluator boundary protects its control, inputs and result channel from the candidate. That boundary is outside this proposal.

## Compiler And Configuration Ownership

The parent compiler resolves the named workflow in the parent's module graph, then builds it as a private child entry through the ordinary closed-program pipeline: reachable static functions, procedures, workflow calls, specialized hooks, types and prompt definitions keep their canonical owning modules; the entry has its own site table, source maps and inferred effect summary; it contains no runtime procedure value, no text to parse at invocation, and no live library lookup. The child need not be exported.

The full dependency closure, owner configuration, source snapshots, logical asset bases and compiler/runtime compatibility identity become an immutable child artifact contribution to the parent's checked program. Provider/command bindings are selected from these protected owning configurations; the clone cannot override manifests, provider registry, prompts or executable configuration. Project files remain workspace data, even if they happen to have `.orc` names. Child compilation uses the same frontend type/effect checks and closed read-back validation as an ordinary entry; do not copy closed nodes while keeping old site ids or reuse retired mode-1 data as permission.

The parent has one `run_ref` effect; the child summary is checked against environment-supported effects without erasing operation kinds. Workflow mode admits the selected target's ordinary pure forms, commands, portable tool-enabled provider calls and static calls, and refuses nested `run-ref`, dynamic evaluation, trial, human input, sessions/context capture, resource transitions and parallel effect execution inside the child. These refusals are transitive by effect kind through calls, procedures and hooks via the closed effect summary. Serial calls/loops provide the motivating flow; further classes require their own authority/recovery qualification.

## Runtime, Environment, And Provisioning

```text
parent evaluator / run_ref prepare-settle-reconcile
  -> verified pinned source + immutable child artifact + explicit input snapshot
  -> host clone on disk (durable workspace, sanitized .git, initial checkpoint header)
     + private control root and memo
  -> trusted child evaluator (host): pure evaluation and static calls
     -> per holder incarnation: delegated scope (limits, OOMPolicy) -> holder bwrap
        (sealed rootfs by fd, --unshare-net, sized tmpfs /workspace seeded from the
         clone, /tmp and HOME, /dev/shm, /result; /dev and /run read-only; ro .git;
         model-only: gateway socket)
        -> spawner (image /bin/sh, host socketpairs) -> one gated setsid leaf per
           command/provider in its own slot, quiesced and killed after each leaf
     -> checkpoint tmpfs -> clone (intent, copy, sync, committed), import result,
        memo commit
  -> terminal: stop holder -> delta/export from the clone -> parent commit
```

The trusted child evaluator is an ordinary host runtime process under its existing child writer lock. It receives the checked child artifact and a runtime-owned, non-serializable execution environment binding: authority carried by runtime construction, not an ORC value. Direct child resume reconstructs it only from checked recorded authority and successful environment revalidation. A fallback to normal host command/provider execution is forbidden.

The image contains project dependencies, the provider executables, the POSIX `/bin/sh`, `/usr/bin/env` and `setsid` the spawner uses and the interpreter of the model-only relay, all under image executable pins, not a competing ORC compiler. The host child evaluator never imports Python from the clone, sources its setup files, runs its hooks, or interprets its `.orc` files. Its private control root is outside the clone, with immutable program/config snapshots and its own run header/memo; a confined child never compiles in the clone and creates no `.orchestrate` entry there. Provisioning is runtime work: resolve the exact revision into the verified source store; import the exact image into the sealed snapshot store, creating the empty profile mount points `/workspace`, `/result`, `/tmp`, `/run`, `/dev` and `/proc` as part of the sealed manifest (every other bind target lives under the `/run` tmpfs); allocate an independent detached clone; validate the baseline and publish its initial checkpoint header; copy explicit typed path inputs; allocate protected child state; then admit process execution. No `:setup` exists for workflow mode and this path must not call the existing host `_run_setup`. Image entrypoint scripts are not executed; the runtime selects the executable and sanitized argv/environment. Installation-time image preparation is outside an individual workflow run; at each holder launch the rootfs is rehashed through a retained directory descriptor and that same descriptor is bound (`--ro-bind-fd`), so a store path cannot be swapped between rehash and launch.

Host Git fetch/clone for this profile runs with a sanitized environment: no credential helpers, no SSH agent, no global/system Git configuration and no proxy environment; it reuses the existing source-materialization refusals. The materializer must leave no alternates, shared mutable object files, worktree links, executable hooks, host-bearing remotes or parent repository links reachable from the mounted clone; `--no-local` alone is not the complete security proof. Submodules and LFS stay rejected under current policy. The self-contained sanitized `.git` is bound read-only from host disk at `/workspace/.git`, outside the tmpfs quota, for local diff tools; candidate commits are not part of this profile. The parent checkout and the mirror are never mounted. Host delta collection uses the existing tree-manifest/difflib path, never repository-controlled Git hooks, filters, external diff or configuration.

**Holder and leaves (D-b, D-g, R4, R5, R6).** A holder incarnation is one `bwrap` process per child attempt and controller session, launched from the controller's main thread (`--die-with-parent`): `--unshare-user --unshare-ipc --unshare-pid --unshare-net --unshare-uts --unshare-cgroup --disable-userns --cap-drop ALL --clearenv --new-session`, the rehashed rootfs at `/` by descriptor, `--dev /dev` with a size-bounded `--tmpfs /dev/shm` and then `--remount-ro /dev`, `--proc`, no `/sys`, size-bounded `--tmpfs` at `/workspace` (`:workspace-mib`), `/tmp` with HOME (scratch constant) and `/result` (result constant), `--tmpfs /run` carrying the host-written leaf directory read-only at `/run/runref` and, for `:model-only`, the gateway socket at `/run/gateway.sock`, then `--remount-ro /run`; the sanitized `.git` read-only at `/workspace/.git`. The launcher sets descriptors 0, 1 and 2 to `/dev/null` and closes everything but the two sockets and the `--info-fd` before executing `bwrap`, so the processes inside the namespaces (pid 1 and the spawner) hold only `/dev/null`, the two sockets and guest-owned objects; the outer `bwrap`, which keeps `--info-fd` and its internal descriptors, is outside the PID namespace and invisible to leaves (N8); F3b asserts the in-namespace claim from a leaf, because a leaf can list `/proc/<pid>/fd` and reopen any pipe or file it finds there. The command is the image's pinned `/bin/sh` running a host-authored loop over two inherited unix stream socketpairs, control and gate: on each request line from the control socket it forks a leaf subshell, acknowledges with the subshell's pid on the control socket, and waits for it; the subshell closes the control socket, blocks on one line from the gate socket, closes it, redirects stdin from the leaf's host-written file and stdout/stderr into `/result/<leaf>/`, and executes the image's pinned `setsid` over `/bin/sh /run/runref/<leaf>/leaf.sh` with cwd `/workspace`, so the leaf runs in its own session and process group and an ordinary `kill 0` or `trap 'kill 0' EXIT` in project code never reaches the spawner; `setsid` must exec in place when its caller is not a group leader, as util-linux does, since a forking `setsid` would break the wait and the pid derivation, so F3b-channel checks that the leaf pid equals the acknowledged pid. When the leaf exits the spawner writes its exit status on the control socket. The script text is host-authored and delivered on the command line; it executes at guest uid and is trusted for nothing: the host trusts only cgroup membership, quiescence, its deadlines and its own bounded reads.

Host protocol per leaf: verify whole-slot quiescence (the `holder` slot's members equal the set recorded when the spawner reported ready; the `host` slot and every leaf slot are absent or empty); empty `/tmp`, `/dev/shm` and `/result` through the root descriptors and create `/result/<leaf>` exclusively; write the leaf script, create the leaf slot and send the request; require the acknowledgement within a fixed deadline, wait until exactly one member beyond the holder set appears, move it into the leaf slot and verify membership; release the gate; wait for the status line, an empty leaf slot or the wall deadline; `cgroup.kill` and `wait_empty` the leaf slot, remove it and the leaf script; require the status line within the deadline; verify quiescence again before any read or checkpoint. Two or more foreign members, or one outside a request window, refuse with `run_ref_environment_escape_rejected` and kill the scope. Exit status and output are untrusted guest data from the candidate's trust domain. A missing acknowledgement or status line, a stopped, signalled or absent spawner, an OOM kill of a holder-slot process or an exited `bwrap` is a **holder death** (R2): the controller kills and empties the scope, appends the failed terminal row (N1) and then `failed` with `run_ref_environment_lost` on the pending attempt, ends the child and returns `FAILED` to the parent with the committed prefix retained as evidence; there is no in-run retry, so a guest that signals, stops or `kill -- -1`s its spawner, or raises its `oom_score_adj` and then exhausts memory, only loses its own candidate. Admission records `kernel.yama.ptrace_scope >= 1`, which with dropped capabilities denies a leaf attach to the spawner. One `DurableLaunchReleaseGate` per holder launch, bound to the scope identity, is the durable release fact; leaves need none because the memo's `started` record and the scope inventory cover them.

**Durable workspace and checkpoints (D-f, R1, R3).** The detached clone on host disk (the existing `workspace.py` allocation, with its sanitized `.git`) is the child's durable workspace; the holder's tmpfs is its execution copy. After provisioning the host publishes the initial checkpoint header (effect identity `none`, ordinal 0, the baseline `freeze_tree` digest, state `committed`). Before the first leaf of each holder incarnation the host seeds the tmpfs from the clone, and after every leaf that reached quiescence by exiting, whatever its exit status (a leaf killed by the clamped provider timeout or by wall exhaustion is never checkpointed, N9), it checkpoints the tmpfs back onto the clone before that effect's memo `committed` record, in two phases: publish the header in state `intent` with the effect identity and attempt ordinal, fsync-durable (file and directory) before the first clone write; copy, hashing while copying so no second read is needed; make the clone's bytes durable (`syncfs` or `sync`); publish the header in state `committed` with the resulting manifest digest, durable before the memo commit (N6). The copier (in `workspace.py`, over `safe_tree`) walks both trees component-wise beneath retained root descriptors; mirrors kinds (a disk entry of another kind is unlinked no-follow and recreated); writes regular files to a temporary name and renames them into place with modes masked to `0o777`; copies symlink targets as strings; removes entries absent from the tmpfs; never writes `.git` or `.orchestrate`; skips sockets, FIFOs and device nodes and counts them in the header and accounting (legitimate tools create them; exporting one still refuses); and refuses an entry under a reserved root with `run_ref_environment_escape_rejected`. Seeding, checkpoint and result import run in a short-lived host helper process that the controller places in a `host` slot of the scope before it touches the tmpfs, so their pages are charged to the scope and never to the controller's cgroup; the helper inherits only the retained descriptors, runs under a parent-death signal and dies with the scope (N4). If the copy fails under a live controller (helper exit or OOM kill, `run_ref_environment_escape_rejected` mid-copy), the controller kills the scope, re-freezes the partial clone, publishes `committed` for that attempt and ends the child with holder-death mechanics (N5); the `FAILED` code stays `run_ref_environment_escape_rejected` when the copier refused and is `run_ref_environment_lost` otherwise (P5). Cost: at most `:workspace-mib` bytes read and written per leaf; all host-side time (rehash, seeding, checkpoints, attempt snapshot copies, result import) is charged to the child's cumulative `:wall-seconds` and recorded in accounting, so no sequence of leaves or resumes performs unbounded host IO; skipping files whose size and digest match the previous manifest is an optimization, not a contract change. The checkpoint is live state, not evidence: it is charged neither to the evidence allowance (D8) nor to `:output-mib`, and it is deleted with the clone at cleanup.

Resume first kills and empties the recorded scope, including the `host` slot, and only then reads the header and validates the clone before any release (N4). A header in state `intent` names an attempt whose copy was interrupted (one naming the last committed attempt is harmlessly re-frozen); the clone is then a partial post-leaf tree, the same baseline today's host model leaves after a crash mid-command, so resume re-freezes it, publishes a `committed` header for that attempt and reruns the attempt under §8.1. A header in state `committed` must match the clone's fresh manifest and must name the last committed attempt or any uncommitted attempt newer than it (a rerun that crashed before its own checkpoint keeps the previous attempt's header); only a digest mismatch, which means host-side corruption of the durable workspace, fails closed with `run_ref_environment_changed` and stops the resume before release. A crash between a `committed` header and the memo commit leaves the pending attempt's post-leaf tree as the §8.1 rerun baseline, the same non-transactional clone contract as today. Cancellation, timeouts and holder death do not checkpoint; the clone keeps the last header's tree. A committed confined effect's resolved input is recomputed from its attempt snapshot and recorded evidence map, never from the current clone (P1), after the snapshot bytes are verified against the digests recorded in `started` (a mismatch is tampered evidence and fails closed, never `effect_input_diverged`), so later candidate edits cannot diverge the committed prefix, a rerun after guest edits is the ordinary non-transactional contract, and no restore of bytes can invalidate the committed digest. Delta, exports and the terminal proof read the clone after the final checkpoint; the holder is stopped at the child terminal and never outlives it.

The provider and command adapters share one confinement launch boundary. Existing request rendering, ordinary memo attempts, command repeat policy, provider result validation and result-bundle transfer remain their owners. Namespace translation maps only the verified candidate root and the current attempt's result scratch. Host absolute paths, run-root FDs, ancestor directories, sockets other than the relay, and host interpreter pins never cross. R2/R3 take a guest spelling for confined attempts: `ORCHESTRATOR_OUTPUT_BUNDLE_PATH` and the prompt's `- path:` line both name `/result/<attempt-relative>`, so prompt identity for confined attempts differs from host attempts by design at the new target. After leaf quiescence the result broker copies validated bytes from the exclusively created `/result/<leaf>` into the protected attempt through the retained descriptor. Forms that would export a private runtime result path, in particular `provider-bundle-path`, refuse at compile time inside confined children with `run_ref_child_transport_unsupported`; the child's `result_root` records the external control root.

Confinement also applies when the trusted host reads candidate-controlled files (D-c). The holder's tmpfs mounts are read by the host only by the copier and the result import, through one root descriptor per mount opened once from `/proc/<holder>/root` right after the spawner reports ready, validated by the `holder` slot's membership after opening, never reopened by path and closed when the incarnation ends; traversal is component-wise beneath it with `O_NOFOLLOW` at every component and `st_dev` pinned to the mount recorded at opening (`openat2` with `RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_XDEV` is an acceptable equivalent), regular files and directories only, symlink targets as strings, bounded bytes. On the tmpfs `st_nlink > 1` is admitted because the device pin already proves both names are guest-owned; on host-disk trees the existing unsafe-hardlink refusal stands. Every other host read (`:doc` fills, dependency/input checks, result validation, delta, export, terminal evidence) reads the host clone through the existing descriptor-rooted owner (`workflow/workspace_files.py`, `_common/safe_tree.py`) after the previous leaf's whole-slot quiescence and checkpoint; a provider that leaves a background tool behind has not completed. Clone files that a stable-command token, a document fill or a prompt dependency names are selected and bound by content at `started` through this same no-follow reader beneath the clone root (a symlinked token binds its target string or refuses, never a host target; selection is replayed from the recorded evidence map on resume, not from the current clone, Q5) into the attempt snapshot (D5, P1); the snapshot is content-addressed against the checkpoint manifest's digests so unchanged bytes are stored once, is checked against the evidence allowance at `started` before any byte is copied, refusing with `run_ref_budget_exhausted`, and its copy time is charged to the wall budget (Q3); declared `closure` entries, interpreters and package closures of confined commands name only image-pinned paths, and a closure that resolves into the clone refuses at dispatch before `started`, surfacing after release as `FAILED` with `run_ref_environment_effect_unsupported` and no attempt record (Q1); the uncommitted attempt's C4 comparison and the precommit rehash (`command_closure_written`) therefore cover image pins only, so a command may rewrite the clone files it names (Q2). A returned typed path is untrusted input to that reader. Confined child headers use versioned **image executable pins**: snapshot digest/platform, guest executable path and immutable executable/config closure. Host `shutil.which`, host package-origin checks and host absolute interpreter substitution do not authorize them. Resume validates the pins and rejects drift before dispatch. Ordinary host runs retain their current pin schema. Each provider timeout is clamped at dispatch to the remaining child wall budget.

## Isolation, Credentials, And Resource Contract

`run_ref_confinement.v1` is a sibling security profile requiring a versioned amendment in `specs/security.md`. It does not select, rename or weaken `provider_phase_isolation.v1`, and it is **not registered in `_BACKENDS`**, so it can never satisfy a `provider_phase_isolation.v1` request. The concurrent open provider-isolation integration (capability matrix, provider-phase isolation row: executor ownership/routing, lifecycle, run/resume, attestation) is a coordination constraint on executor routing: both profiles route through one executor seam, and neither may be integrated by special-casing the other.

**Containment scope (D-a).** Each holder launch runs inside a transient delegated scope that the controller creates with `systemd-run --user --scope --unit run-ref-<launch-token-prefix>.scope -p Delegate=yes -p MemoryMax=<:memory-mib> -p MemorySwapMax=0 -p TasksMax=<:pids> -p CPUQuota=<:cpus x 100>% -p OOMPolicy=continue` around a gated launcher: a host shell that reports its pid over the launch pipe, waits for one line, and executes `bwrap` only if that line equals the release token it was given, exiting on EOF or mismatch, so a controller crash before release never starts a holder. The controller resolves the scope cgroup from the launcher's `/proc/<pid>/cgroup`, validates it with the discovery identity rules unchanged (trusted cgroup2 mount, euid-owned, not group/other writable, `cgroup.procs`/`cgroup.events` present), moves the launcher into the `holder` slot, verifies that the scope root is empty, reads back `memory.max`, `memory.swap.max`, `pids.max`, `cpu.max` and `OOMPolicy`, and only then releases. `CgroupV2ContainmentRoot` gains a constructor from that explicit path, and `create_slot`/`load_slot` take their name prefix from the profile (`run-ref-`), so the `holder` slot, the `host` slot and one slot per leaf are its children; membership, `populated`, `kill`, `wait_empty` and `remove` are reused as they are. Admission refuses with `run_ref_environment_unavailable`, at the first launch and at every later incarnation, when `systemd-run` or the user manager is unavailable, delegation is refused, a controller is missing from the scope's `cgroup.controllers`, or a limit or policy differs from the request; F3b measures that limits set as unit properties are enforced. The controller is never re-executed, so public `run`/`resume` entry is unchanged. `provider_phase_isolation.v1` keeps `discover()` of the controller's own cgroup; the two roots never share a path. Recovery inventories the recorded scope unit and cgroup identity: a populated remnant is killed through `cgroup.kill` under the writer lock; an absent scope means the holder died with the controller.

Required positive evidence covers unprivileged host launch through the existing fixed `bwrap` authority; private user/PID/mount/IPC/UTS/cgroup/network namespaces; all capabilities dropped; no privilege gain; sealed read-only imported rootfs; bounded temporary mounts with `/dev` and `/run` read-only; no inherited host descriptors beyond `/dev/null` and the two spawner sockets in any in-namespace holder process (pid 1, spawner); a positive mount allowlist; `memory.max`/`pids.max`/`cpu.max` enforced on the scope as unit properties; workspace quota enforced; the spawner's channels unreachable from leaves; leaves in their own sessions; whole-slot quiescence before every host read; and no committed effect lost by a holder death. Host `/`, home, parent/peer workspaces, cloud credentials, SSH agents, engine sockets and orchestration state are absent. Reuse `DurableLaunchReleaseGate` for the durable release fact, `CgroupV2ContainmentRoot`/`Slot` for containment and quiescence, the result broker for transfer and `isolation_network_preflight.py` for the denied-endpoint inventory.

Tool-enabled provider processes run inside the same confinement as commands. Their child shells, filesystem tools, plugins and subprocesses cannot leave it. Provider CLI flags that bypass internal approvals do not establish outer isolation. A normal authenticated host SDK process is not a permitted alternative. For `:none`, commands and providers get no network. For `:model-only`, the network namespace is still unshared and only a bound unix socket enters the sandbox; a host-authored relay started inside each provider leaf under an image executable pin forwards loopback to it and dies with the leaf's quiescence (R4); the socket leads to a host-owned inference gateway that accepts only the admitted provider/model API operations with request/response byte limits, an attempt-bound capability, expiry and token/cost/request ceilings from installation policy. It chooses a fixed configured upstream; no arbitrary URL, CONNECT proxy, redirect authority, host tool call, filesystem API or credential read is provided. The capability is revoked when the attempt stops and is excluded from durable artifacts; the leaf script that carried it is removed with the leaf.

**D7, inference gateway prerequisites**, each unbuilt today: a per-attempt environment/config overlay outside R8/R10 (evaluated providers set only `ORCHESTRATOR_OUTPUT_BUNDLE_PATH`, and the executor copies `os.environ`); profile-specific provider template variants (`registry.py` templates are fixed host argv with no base-URL/config injection) that name the image executable pins of the provider CLIs rather than host binaries; telemetry and non-model traffic disabled; the per-leaf unix-socket relay, because `--unshare-net` leaves only a bound socket and neither CLI speaks HTTP over a unix socket; a gateway implementing the streaming Responses/Messages APIs the CLIs use; API-key accounts only, because OAuth file passthrough (`~/.codex/auth.json`, `~/.claude/.credentials.json`) is forbidden, which may change billing and model availability. Reason: these are the concrete gaps between today's executor and a confined provider; naming them prevents a mounted-home shortcut. It makes harder: providers arrive later than commands. **Increment A: confined commands and `:network :none`; providers refuse with `run_ref_provider_transport_unavailable`** until F4 passes, so the profile can be admitted before transport is qualified.

Resource enforcement includes CPU, memory, process count, cumulative child wall time including the host-side work done for the child (R3), workspace/scratch bytes, exported bytes/file count/depth, and bounded stdout/stderr. Post-run `du` is insufficient. Resume charges elapsed/resource/provider budgets to the existing child, not a fresh allowance. An oversized artifact, fork bomb, lingering daemon, output flood, decompression bomb or failed quiescence cannot proceed to export. **D8:** protected evidence snapshots are charged against a separate installation-policy evidence allowance, checked at each effect commit before the next dispatch and at `started` before an attempt snapshot is copied (refusing with `run_ref_budget_exhausted`, Q3), never against the author's `:output-mib`, which covers exports only; reason: evidence size is a runtime property authors cannot predict. It makes harder: two allowances to explain. Limits and effective kernel settings are retained in admission evidence.

**Memory headroom (D-d, R7).** The tmpfs mounts are charged to the scope's `memory.max` and their pages are not reclaimable, so every writable tmpfs is sized and every other tmpfs is read-only: the profile fixes scratch (`/tmp`, HOME) at 256 MiB, `/dev/shm` at 64 MiB, the result ingress at 128 MiB and a process headroom of 512 MiB, remounts `/dev` and `/run` read-only after their binds, and the compiler refuses a policy whose `:memory-mib` is below `:workspace-mib + 960`; a full workspace then returns `ENOSPC` before the scope limit. The rule is compile-time because every term is a literal or a profile constant; installation maxima are rechecked at admission. Anonymous and SysV memory are process memory under the headroom and the OOM killer; SysV segments a leaf leaves behind persist in the holder's IPC namespace until the holder ends and only starve that candidate's own later leaves. The scope is created with `OOMPolicy=continue`, read back at admission, so a systemd default `OOMPolicy=stop` cannot stop the whole scope on one OOM kill; a process OOM inside the scope selects by badness (the writer, in F3), and a holder-slot victim is a holder death (`FAILED`), since the holder cannot be shielded without `CAP_SYS_RESOURCE` and a leaf may raise the spawner's `oom_score_adj`.

## Results, Paths, And Lifetime

Preserve the envelope's three fields. Pure scalar/record/union/list/map values cross through the existing canonical descriptor checks. `.workspace_delta` remains a normalized bounded baseline-to-final description, not authority to read arbitrary clone files. `.accounting` includes the existing child accounting and actual provider usage; unavailable usage is explicit, not zero. For this profile the `RepositoryRevisionId` setup component is the literal `none` and `setup_ms` is `0`; the image digest belongs to environment admission, not the revision id.

**Chosen path rule: export copies while preserving the original declared root.** Every recursively returned path leaf is an explicit artifact declaration, as in current run-ref. This profile admits output path descriptors only when they have a nonempty workspace-relative `:under` root outside reserved control/Git roots and `:must-exist true`; a descriptor with `:must-exist false` refuses at compile time with `run_ref_child_transport_unsupported`. Each returned path must exist, stay below that declared root, and identify a regular file or bounded directory tree without symlinks, special files, unsafe hardlinks or nested mounts.

For a child path `artifacts/candidate.py` of nominal `CandidateFile :under "artifacts"`, the runtime copies into:

```text
artifacts/.run-ref-exports/<parent-run>/<activation>/<attempt>/candidate.py
```

The suffix is the original path relative to its own descriptor's `under`, and the destination is below that same `under`. Identical child paths share one copied object; conflicting descriptors/roots or destinations refuse. The compiler rejects a descriptor whose refinements cannot survive this mapping; the boundary validator independently checks the original child value and the rebased parent value against the same complete descriptor. This is not generic string prefix replacement or a nominal cast. The host performs export from the clone after the final checkpoint, never from a holder, using retained roots, no-follow traversal, exact byte/count limits and atomic no-overwrite publication. Parent destinations are reserved per run/activation/attempt, cannot overwrite existing user files, and are recorded in the same settlement proof as child original paths, result field locations, sizes and digests. A corrupted or missing export refuses; it is not regenerated by rerunning a child. Exports live for the parent run's lifetime and are removed with run deletion/invalidation; the example README recommends ignoring `.run-ref-exports` in VCS. Input paths follow the converse rule: copy explicitly declared bytes into a child-owned location still satisfying each input descriptor, reject unsafe links and revalidate before launch.

After terminal validation, export (none for `FAILED`) and successful parent settlement of either outcome, the existing run-ref coordinator initiates deletion of the settled workspace (the clone and its checkpoint header), recording cleanup intent/completion in the ledger under the parent writer lock; K4's never-discard protects a live child, not a settled one; it first revalidates the exact owned root, the absence of a live scope and quiescence and never deletes a pending/live workspace. Protected child artifact/header/memo, failed terminal row, environment admission, baseline/final manifests, delta, accounting, export manifest and committed exported bytes are kept for the parent run's retention lifetime and suffice for settled reuse without the clone. Cleanup failure retains the workspace and records a pending obligation. **Completed-resume cleanup amendment** to `specs/cli.md` ("a completed run resumes to its recorded terminal with exit 0 and no write"): a completed run with a recorded pending cleanup obligation retries it on resume and records the outcome; otherwise no write. No new GC command or retention framework is introduced.

## Lifecycle, Cancellation, And Recovery

Keep one `run_ref` effect class, one visit identity derived from the parent's semantic site/activation, one `run-ref-attempts.jsonl` owner, and the existing prepare → parent memo commit → settle protocol. Workflow mode uses `run_ref_static_config.v2` with its checked child contribution, operand schema and `run_ref_confinement.v1` policy. The resolved revision is an ordinary reached effect input. Version the private request/proof and discriminate recovery by validated profile; old ledger rows keep their meaning. Allocation durably binds resolved revision, child artifact/config, inputs, environment, child run id, workspace/control roots and cumulative budget before releasing candidate processes. Each holder launch gets an attempt-bound containment identity (the scope) and a durable release fact through `DurableLaunchReleaseGate`; the inventory distinguishes allocated-but-not-released from possibly released before adopting, cancelling or retrying.

**D3, pending-effect recovery.** Confined children follow EE §8.1 and §8.2 rather than a new stop code. A `started`/`failed` child attempt with no commit reruns on resume unless its boundary declares `must_not_repeat`, after the existing C4 implementation-file drift checks; tool-enabled provider attempts are portable calls and take the same rule. A leaf that ends in failure inside a live controller, including holder death, follows §8.2 and surfaces as `FAILED` (D6); the rerun rule serves controller interruptions. The `FAILED` decision is durable (N1): under the parent writer lock, which owns `run-ref-attempts.jsonl`, the coordinator appends a failed terminal row (code, detail, accounting, memo prefix digest) before the memo `failed` record (child writer lock) and before preparing the parent value; a crash before that row is a controller interruption and the attempt reruns, while after it the child is terminal and never reruns, whatever the number of committed effects (P2); a crash between the row and the memo record is repaired on resume, when the row names a started attempt, by appending the missing `failed` record and the child's failed terminal from the row under the child writer lock before the value is prepared (P3); a row for a dispatch refusal before `started` names the refused site and no attempt, and no record is invented (Q1). Reason: the runtime already owns an at-least-once contract with drift checks; a second rule for the same attempts would fork recovery semantics. It makes harder: an interrupted tool-enabled attempt may repeat its tool work in the same clone; the clone is not transactional.

| Interruption point | Recovery for `run_ref_confinement.v1` |
| --- | --- |
| Before the holder is released | No live process or release fact: discard and retry provisioning under today's K4 (fresh allocation). |
| Holder released, no child effect committed, no failed terminal row | Inventory and kill the scope remnant under the writer lock. Today's K4 applies: the child may be discarded and reallocated, or resumed with a fresh holder seeded from the clone, the pending attempt following §8.1; `invalidate` remains available. A failed terminal row takes precedence over this row (P2). |
| At least one child effect committed, child incomplete | Retain the same child run and clone. Kill the scope remnant, validate the clone against its checkpoint header, start a fresh holder incarnation seeded from the clone, then resume the child's ordinary memo: committed effects are reused, the pending attempt follows §8.1 (rerun unless `must_not_repeat`), budgets are cumulative. |
| Controller dies during a checkpoint (header in state `intent`) | After the scope, including the `host` slot, is killed and empty: the clone is a partial post-leaf tree of an uncommitted attempt; re-freeze it, publish its `committed` header, then continue as the previous row; the attempt reruns under §8.1. |
| Rerun crashed before its own checkpoint (header names an older uncommitted attempt) | Accepted: the header names an uncommitted attempt newer than the last commit and the clone matches it; the clone is the rerun's baseline, then as the row above. |
| Holder dies while the controller lives | Not a controller interruption and not retried in the run: the controller kills and empties the scope, appends the failed terminal row and then `failed` (`run_ref_environment_lost`) on the pending attempt, and returns `FAILED` to the parent with the committed prefix retained as evidence; a later explicit `resume` finds the parent's committed memo and dispatches nothing. |
| Child failed terminal durable, parent has no commit | Revalidate the failed terminal row against the memo prefix and prepare the same `FAILED` value for the parent commit; never rerun the attempt or start a holder (N1). |
| Child terminal durable, export absent or partial | Revalidate the same terminal, reserve/reuse the same export destinations and finish atomic publication from the clone after its final checkpoint. Never dispatch a child effect or start a holder to rebuild it. |
| Child terminal and export prepared, parent has no commit | Revalidate retained terminal/export evidence and prepare the same value for the parent commit. |
| Parent committed, not settled | Validate the inline proof and finish existing settlement without launching a child. |
| Parent settled, clone removed | Reuse protected child/proof/export authority; no clone, holder or provider launch is required. |
| Cleanup obligation pending after completion | Retry the recorded cleanup on resume and record the outcome (completed-resume cleanup amendment). |

**K4 amendment scope:** a confined child with at least one committed effect or a failed terminal row is never discarded; a confined child with zero committed effects and no failed terminal row keeps today's K4. **K8:** no-supersession applies from the first committed child effect, not before; `invalidate` stays available while no child effect has committed. Starting an explicitly new top-level run is distinct from recovering this run and claims no rollback. Missing authority, containment identity ambiguity, tampered memo, inconsistent release facts, a clone whose `committed` header digest no longer matches or lost control state fail closed with the retained evidence intact; `run_ref_environment_unavailable` and `run_ref_environment_changed` stop a run or resume before release and never produce `FAILED`. `must_not_repeat` on a pending attempt after the first commit stops the run permanently, since K8 forbids `invalidate`; this follows EE and is a named dead end.

The terminal proof replaces the pure-child sole-terminal test only for this profile. Capture protected header, checked artifact and complete memo prefix once under retained roots; require a completed terminal, valid committed-effect proofs and no unfinished/unsettled effect. Replay pure control with the ordinary evaluator and those committed values, matching every reached commit in order by site/activation/input authority from retained attempt snapshots, without dispatch, reconciliation or reading mutable clone dependencies. Check canonical equality of replayed halt, terminal value and the child's direct typed result, and bind that evidence to the parent settlement before path export transforms the value. Before clone cleanup, preserve the exact result bytes, bound input values, rendered prompt/dependency snapshots, command closure/input witnesses and configuration assets the shared read-only validators require, charged to the evidence allowance (D8). Missing snapshots block settlement/cleanup rather than being reconstructed from current source. For `FAILED` the proof is the committed prefix with valid proofs, the failed terminal row (code, detail, accounting) and, when the row names a started attempt, that attempt's `failed` record (appended from the row on resume when the crash preceded it, P3); for a dispatch refusal before `started` there is no attempt record and the row names the refused site instead (Q1); no later attempt exists; pure control is replayed to the failed site over the committed values, settlement binds it the same way, and settled cleanup then deletes the clone without export (N1).

Cancellation and wall-time exhaustion first stop every scope member (`cgroup.kill` on the scope), revoke the model capability, prove quiescence without checkpointing the killed leaf, and then record the outcome: `FAILED` to the parent when the child cannot continue, or a pending child under the table above. If the controller dies, recovery inventories its recorded scope identities; a stray member never justifies allocating a replacement child.

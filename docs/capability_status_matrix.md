# Capability Status Matrix

Status: informative routing/status index
Normative authority: `specs/` for runtime/DSL behavior; linked design docs for Workflow Lisp/frontend contracts
Scope: public authoring/runtime surfaces that maintainers may inspect, invoke, adapt, or depend on

This matrix is a discoverability layer. If it conflicts with a normative spec,
the spec wins and this matrix should be fixed.

Examples in this matrix are routing pointers, not automatic templates.
Use the route-readiness registry and its current owner evidence to decide
whether a workflow is suitable for copying. Modification age alone does not
establish or disqualify readiness; revalidate adaptations for the task shape.

Current execution scope: the [selected executor retirement](design/workflow_lisp_executor_retirement.md)
rejects executable entries through 2.34 and old-profile resume/invalidation.
Targets 2.35/2.36, bounded 2.37 and the bounded 2.38
[Agent Sessions extension](lisp_workflow_drafting_guide.md#agent-sessions-target-238)
and [command-only confined children](lisp_workflow_drafting_guide.md#confined-workflow-children-target-238-command-only)
use evaluated execution; public confined providers remain closed. Source
compilation, imports, REPL loading and LSP analysis require every module to
meet the [2.35 source floor](design/workflow_lisp_executor_retirement.md#source-floor-235);
the registered source range is 2.35–2.39, including retained typed-program capsules.
Target 2.39 adds inference-default procedure contracts and bounded
[phased provider delivery](lisp_workflow_drafting_guide.md#authoring-phased-contract-delivery-target-239).
Imported 2.35–2.38 definitions retain their original contracts and qualification limits.
Historical read-only data access does not compile old source. Availability of a
shared service, type, or historical test does not admit an excluded effect.
The [retirement closeout](reports/2026-10-13-best-of-n-and-executor-retirement-closeout.md)
owns gate R, exact recovery qualification, final verification and delivery.

Evidence links distinguish current owner checks from preserved historical records.
A historical test or versioned format is not executable qualification.

Status labels:

- `Implemented`: available in current checkout with runtime/test/spec evidence.
- `Partial`: available for some routes, but incomplete or bounded.
- `Library`: available as a library/frontend abstraction rather than a raw DSL primitive.
- `Designed`: design exists, implementation is not complete enough for normal use.
- `Planned`: roadmap position and a gated plan exist, but the governing design
  is not yet accepted and implementation must not begin.
- `Future`: intentionally deferred.
- `Retired`: removed from the live product/evidence surface; retained references
  are historical provenance only.
- `Legacy`: retained for compatibility or historical examples, not preferred for new authoring.

# Functional Calibration: Filesystem Isolation And LS8 Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the comparison harness's shared host filesystem with a small positive mount boundary, then complete a fresh LS8 functional difficulty comparison under the unchanged scientific rule.

**Architecture:** One compare-owned Bubblewrap builder starts from an empty root and exposes only declared operating-system/tool dependencies, the current unit's writable tree and private persistent home/temp, and the exact read-only clone grants derived from a judge's finalized validated score-input batches and any explicit reference admitted by its rubric. LS8 specifically uses four anonymous clones per task and no reference. Durable private-home backing stays outside candidate trees and every public records/capture tree. Preparation records each unit's home so launch, resume, scanning and metering use the same authority; existing historical records keep their original home interpretation. No orchestrator rootfs/cgroup framework, public isolation profile, generic policy language or shared-root fallback is selected.

**Approach and tradeoff:** Remove ambient host access rather than extend the directory denylist. Implicit shell setup, provider configuration and tool dependencies become unavailable unless explicitly admitted and proven; adding tools later therefore requires updating and verifying the concrete mount closure.

**Tech stack:** Existing Python standard-library comparison helpers, shell shim/model guard, Bubblewrap, Git, tmux and the installed native provider CLIs. Provider execution is blocked until offline feasibility and independent reviews pass.

1. A settled failed ordinary command with policy `reuse_validated_structured_output`, or a selected Workflow Lisp call, may resume only from its **present, integral, matching node-local checkpoint** with valid/restorable `restore_payload`. The checkpoint must match the exact current failed row's identity and visit against `step_visits` and frame identity under the existing checkpoint convention (selected callee frame for a call-boundary record, containing frame for a command record); never rewrite or backfill these identities. Call entry prefers the validated running lineage member; otherwise it resumes the latest validated failed member in the same frame, preserving already committed inner effects. It does not allocate a fresh retry for this qualified case.

Unknown/interrupted attempts do not satisfy this settled-failure exception; existing interruption routes and their barriers remain unchanged. Never upgrade an existing unprofiled root/frame to qualify it. Absent-profile historical frame selection and restoration remain unchanged.

## Contract delta to review before implementation

### Form and checked control

```lisp
(list/map-effect ((repo repos)) :max 8 :parallel 4 :workspace repo
  (call implement-one :task task :repo repo))
```

Omitting `:parallel` preserves the existing serial rewrite and artifacts exactly. For the new form, require a positive integer literal concurrency bound and an explicit pure workspace expression in the item binder's scope. Preserve the existing one-effect-or-call body, pure source/arguments, transportable collection/result types and admitted transitive effect classes. Calls can contain admitted sequential control and further maps; do not silently turn a nested map into a compiler gap.

Evaluate the source once and fix its items before starting the batch. Retain `:max` as the item cap, not an effect counter; for the new form reject a list exceeding it before any item starts, printing actual length and limit. Resolve all item cwd expressions before launch and reject duplicate resolved directories with `parallel_workspace_shared`, item indices and source location. Accept existing directory paths (String or the existing compatible path type), resolved relative to the run workspace; canonical aliases to the same directory count as duplicates. Do not create repositories or scan command closures here. An empty input returns an empty list without workers. Concurrency one uses the new item identities/cwd semantics; it is not the historical serial form.

Carry source, item binder/type, body/result type, item cap, parallel bound, workspace expression, authored binder label and provenance in one checked control node. No function-valued language object or new effect class is needed. Its static body sites include `par-map:<binder>[*]`; dynamic indices are zero-based input indices. Source/workspace expressions have no effect sites. Calls and loops inside an item retain their existing frames, labels and dependencies. The result list preserves input order, independent of completion order; dependencies include the source/workspace values and item results, without inventing serial dependencies between independent siblings.

### Execution and failures

Use one bounded `ThreadPoolExecutor` for an active batch and a `Queue` of private requests to its existing run coordinator. An item evaluates its body in one worker; its effect callback asks the coordinator to prepare/reuse an effect, performs only the admitted external work, then asks the coordinator to validate/publish the outcome. Workers never append the parent memo, publish its view, allocate its ordinal, reconcile a coordinator or hold the parent writer lock. They may write their own exclusively allocated attempt evidence through existing performers. Every future receives a result or an exception; failure paths must not strand a worker waiting for an acknowledgement.

Extract preparation, external performance and finalization from the existing `_execute_effect` lifecycle once, and have serial execution call those same functions directly. Preserve `started` synchronization before allocation/dispatch, typed-result validation and C4 rehash before `committed`, then K3 settlement. A small typed prepared-attempt value is sufficient; no dispatcher registry, abstract executor or plugin protocol. Keep `append_record`, allocation and settlement as the actual durable seams so fault tests still intercept them.

All sibling items settle even when one fails; pending siblings still get their bounded turn. Preserve successful commits and report failure after the batch drains. Select the lowest failing input index for the map's reported error, while retaining every attempt's own failure evidence. No successful effect retries just because another item failed. The parent terminal is published only after all started work and required settlements are clear. A journal/view publication failure stops new reservations, releases blocked request waiters and preserves durable evidence; it is not treated as an ordinary item failure that permits further writes. Resume applies existing retry and `must_not_repeat` rules per identity.

Nested batches share the same parent memo coordinator, not nested writers. A nested batch may own its own bounded executor; do not submit child items to a saturated pool whose parent workers wait for those same slots. The bound is per authored map, as §11 states, not a new global resource budget. This deliberately leaves global concurrency limits and adaptive scheduling harder to add; neither is needed for the fixed best-of-N batch.

### Cwd and logical workspace — concrete D2 replacement

These clauses replace the failed cwd-relative R2 proposal. They apply only to a checked parallel activation at D1's selected target, including concurrency one and sequential calls inside an item. Outside that activation retain the existing protocol, subject only to the reserved-environment clearing exception below. Keep `run_root`, header/rebuild inputs, configuration/source roots, typed path interpretation, artifact validation and stored result locators rooted in the outer run workspace. The item cwd is process launch context, never a replacement `RunAuthority` or `parent_workspace`.

Bind `launch_cwd` in each reached effect's existing `input_parts` map as the digest of its resolved cwd locator: relative to the resolved outer workspace when contained there, absolute otherwise. Preserve workspace-expression dependencies; this locator does not change effect identity. Runtime C7 re-resolves it in journal-offset order; a changed alias diverges before reuse, while whole-workspace relocation retains contained relative locators. Runtime-owned absolute launch coordinates are not added to the header, memo schema, document bytes, authored argv digest or prompt text. Replay discovery and views evaluate workspace expressions as pure values only; directory existence, `Path.resolve` and duplicate-alias checks are runtime work, not view reconstruction.

**C2: literal argv, actual relative lookup.** Leave every authored token unchanged, apart from the existing C3 replacement of a bare interpreter by its pin. For automatic stable-command selection, a relative token is looked up using its original spelling under the actual item cwd. Keep bare argv[0] under C3, slashed relative argv[0] mandatory, other relative tokens selected by existing final-entry `lstat` rules, and all existing homonym/error/prior rules. Absolute tokens retain the current automatic scope: the normalized lexical outer-workspace prefix; an absolute token outside it still needs an explicit closure to bind its bytes. An outer relative script does not automatically run from an item cwd: authors use an absolute path or package invocation when that is their intent. C2 selection establishes bytes, never an argv role, and cannot authorize rewriting a token.

Encode each selected relative token using the **existing** positional `[base,path,position]` key. Join the normalized resolved item cwd with the original token spelling, remove only empty/`.` components for the key, and anchor lexically under the resolved outer workspace when its components have that prefix; otherwise use existing `base: absolute`. Preserve `..` in the key and original spelling for lookup, including symlink/component order. Continue recording resolved symlink targets with the existing encoding. Prior positional evidence is recomputed from the same token, cwd and encoding, then required even if its final entry disappeared. Update first capture, retry, committed C7 and C4 rehash together; permit the existing absolute base for positional prior keys only in this new activation. Unpositioned explicit closures retain their declared workspace/package/absolute owner and lookup base. This needs no new evidence base or wire field. Old serial C2 and its prior-key checks stay unchanged.

**Runtime IO coordinates.** Commands in the new activation receive an absolute, lexically normalized `ORCHESTRATOR_OUTPUT_BUNDLE_PATH` naming their pinned attempt `result.json`; external typed-input documents receive an absolute runtime-generated final argument naming that attempt's `inputs.json`. Providers retain their existing absolute R2. Certified inline JSON, document content, authored argv and typed `relpath` values are not rewritten. X4, memo locators and R3 remain outer-workspace relative. `emit_structured_result` requires an absolute R2 when the new logical-root coordinate is active; a supplied relative destination refuses in that activation. With no active coordinate it retains its old relative validation. Missing result files still use the existing performer refusal. This separates the trusted runtime destination from authored paths; `workspace_relpath` and every authored shape/containment/symlink check remain intact.

The coordinate is **`ORCHESTRATOR_WORKSPACE_ROOT`**, a nonempty absolute outer-workspace path supplied only from retained runtime authority. Give the command/provider launchers a small internal optional `logical_workspace_root` argument, default `None`; do not accept its authority from ambient environment, authored env, provider params or input JSON. After ordinary environment/secrets/overlay composition, remove this reserved key and inject it only when that argument is supplied by the checked parallel performer. Apply the same rule in both evaluated and legacy calls through `StepExecutor.execute_command` and `ProviderExecutor.execute`; the default always removes inherited/authored values, including empty values. The run-reference child launcher also removes it. A nested orchestrator process may inherit the parent's variable as ordinary process state, but its launchers clear it and derive any later parallel coordinate from **its own** run authority. Do not mutate process-global `os.environ` or add a general environment policy. This one reserved key's removal outside the activation is an explicit old-route environment-parity exception; all other historical request bytes and semantics remain unchanged. Standalone adapter helpers treat absent/empty as legacy cwd, and reject an invalid nonempty root rather than silently falling back. Runtime launchers never emit empty or relative roots.

Adapt `validate_review_findings_v1` at its existing carrier-file lookup and findings containment boundaries to that logical root, using legacy cwd when inactive. Absolute carrier arguments keep their existing meaning; inline JSON remains inline. Relative `items_path` values still require `artifacts/work`, prohibit absolute/`..`, and pass the existing resolved containment checks against the logical workspace. Returned relative paths therefore refer to the same bytes the runtime validates. Package-origin validation continues to inspect the actual launch cwd; declared package closure remains package-rooted. External commands must use this documented coordinate for typed relative data; the runtime neither infers operand roles nor rewrites arbitrary argv or JSON strings.

For providers, add one fixed protocol block to `evaluated/prompts.py` after ordinary authored/dependency/typed-input composition and before output-contract insertion, only while the new activation is active. Its instruction is: **“Resolve typed workspace-relative input paths and declared relative output/artifact paths against the directory in `ORCHESTRATOR_WORKSPACE_ROOT`, not the process cwd. R3's relative destination and output positions remain unchanged; the fixed block is part of the new prompt digest. Arbitrary prose strings remain the author's responsibility. Separate provider executor instances retain the outer configuration/workspace authority while R6 uses item cwd.

**Coordinator exception to §11.** Direct command/provider effects use item cwd. A path run reference keeps outer `parent_workspace`, request/proof/ledger authority and its existing child clone allocation; its child executes in that separately governed clone workspace, never the item's cwd. Bind the parent item's cwd/dependencies as above but do not substitute it into child authority or invent a caller-cwd wire field. Per-adapter version copies cannot preserve a whole-package pin. ### Resume and derived views

The current runtime and view replay require active commits to be reached in one global source/journal order. That is incompatible with valid interleaved item commits. Change only the parallel region's order relation: each item's sequential effects retain strictly increasing commit offsets in evaluated source order, and each successor's relevant `started` must follow its predecessor's `committed` (plus `settled` when required). Siblings can interleave, and the continuation after the map is reachable only when every item has a result. A post-map start/commit must follow the completed map's commits and required coordinator settlements. Enforce both order and this barrier even when `depends_on` is empty; a consumed-identity set alone is insufficient. A relevant start is the `(identity, attempt)` start supporting an active reached commit or an active reached pending frontier; locate it in `snapshot.entries`. Do not treat failed/invalidated historical attempts as active successors or use `latest_starts` without this relevance check, so valid C8 retries remain legal. Apply the same structured relation to nested maps, without imposing serial order on their independent children. Old serial order checks, including rejection of reordered serial commits, remain effective.

Use one read-only traversal for runtime preflight and source-free view reconstruction. **Phase one discovers structure using stored typed commit values only**, not `_replay_committed_effect` input resolution. Workspace expressions are pure data here: no directory checks, `Path.resolve`, alias detection or closure IO. C7 validates reached cwd evidence in phase two; the complete fixed cwd list is checked only before live batch reservations. Pause each item at its first missing effect and visit all sibling prefixes; never fabricate a missing value to evaluate a downstream branch. Keep a consumed-identity set and the structured offset-order checks, rejecting duplicate, orphaned, out-of-range, unreachable or impossible dependency evidence. Every pending start must correspond to a reached retry frontier; authorizing sibling starts cannot legalize pending evidence in an unreachable branch or item. A partial item replays its committed prefix and later executes only missing effects; a completed item may reevaluate pure expressions but dispatches nothing. No item-completion record is added.

**Phase two of runtime preflight** resolves and validates the discovered committed-effect requests in **journal offset order**, so C7 still reports the first divergent commit before any dispatch, reconciliation, tail repair or view replacement. Then check every reached retry frontier. A missing effect in one item is not permission to ignore a later committed sibling. Serial continuations, nested maps and data-dependent item bodies must preserve reachability, not merely accept an unordered set of identities. Completed resume is read-only; incomplete-tail handling retains the existing rules.

An item-local pure fault prevents that item from producing a result but does not stop discovery of sibling prefixes. After sibling discovery, still reject that item's unreachable pending starts/commits; do not turn an orphan or `MemoError` into an ordinary item failure. An unsettled run-reference commit can supply its stored typed value during read-only discovery, while the complete prefix is checked before any reconciliation. It never establishes terminal completeness until its settlement obligations are discharged. For effects in a new parallel activation, historical continuation evidence is also constrained: a sequential successor's relevant `started`/`committed` rows, and any post-map start/commit, must follow the required `settled` offset of every coordinator preceding that continuation. Use existing `snapshot.entries` offsets; no new record or format. Reject a late settlement even if the final snapshot now lists that coordinator as settled. Stored-value discovery may examine the continuation but cannot legalize its premature evidence. Preserve old serial behavior outside maps and the distinction between an ordinary item failure and invalid journal authority.

Views use stored values only, never filesystem input resolution or worker creation. Existing effect rows can show multiple running/settling identities; keep `current_step`'s latest-in-flight summary and avoid a new persisted progress format. A view is complete only if the evaluated halt agrees with the terminal and all work is settled. C8 remains whole-journal-suffix invalidation, even when that suffix contains independent siblings; it is not dependency-scoped invalidation. Committed coordinator suffixes remain non-invalidatable.
